# 桌遊基本資料改成所有 domain 共用的 `games` 表

規則書入庫（`rules_ingest`，8 大類各一款）、規則問答、戰績等功能都會提到同一批桌遊，需要統一的桌遊編號與名稱。因此桌遊的基本資料（`games`）、8 個類型（`game_types`）與每款桌遊的類型（`game_game_types`）改成所有 domain 共用的表：表名不用 domain 名稱開頭，所有 domain 都可以直接查詢。`games.id` 是整數（bigint），立倫在空的資料庫匯入一次 `games.json` 時由資料庫自動給號，1–4 號固定是 4 款 Demo 遊戲（血與刃的白薔薇、阿不思學院、馬可波羅、阿瓦隆）；`games.json` 只是請 Codex 整理的臨時資料，匯入後就不再使用。其他組員執行同步指令，把立倫匯出的資料寫進自己的資料庫，所以每個人的桌遊資料與編號完全相同，講「3 號」都是同一款。這三點都和 AGENTS.md §4.2、§4.4 有出入；立倫在 2026-11-11 決定以例外處理，不改 AGENTS.md，理由寫在建立資料表的 MR 說明，由組員在 MR 審核時確認，確認後本檔改成 accepted。這也推翻了 games_advisor 原本「桌遊資料只供推薦，不給其他 domain 參照」的決定。

不用 UUID 的理由：AGENTS.md §4.4 規定主鍵用 UUID，是為了讓發牌機、App 離線時也能自己產生不重複的 ID。桌遊只由立倫的匯入指令寫入，不會有離線產生的情況；整數編號好讀，而且資料庫會檢查型別。

## Considered Options

- **歸 games_advisor 管（`games_advisor_games`），其他 domain 呼叫它的 service**：符合 AGENTS.md，但每個 domain 要對齊桌遊編號都得多一層 service 呼叫，而且類型查不到。
- **主鍵維持 UUID，另加一個數字編號欄位**：符合 §4.4，但組員溝通、寫測試資料時用的是 1、2 這種編號，兩套 ID 容易混用。
- **編號是 "1"、"2" 這種字串，由立倫手動指定**：本檔最初的做法。2026-11-12 組員在 MR #22 改成整數、由資料庫自動給號，讓資料庫限制型別，新增時也不用手動給號。
- **每個人各自匯入 `games.json`，由各自的資料庫照順序給號**：不用同步，但只要有人匯入順序不同或中途刪過一款，同一款桌遊在不同人的資料庫裡編號就不一樣。

## Consequences

- 共用表由立倫負責，程式放在 `backend/app/core/games/`（資料表定義與唯讀查詢）。只有 games_advisor 的兩個指令會寫入：立倫執行的「匯入桌遊」、其他組員執行的「同步」。其他 domain 改這三張表要 @ 立倫。
- 資料怎麼流到每個人的資料庫：立倫匯入 `games.json`（只有一次）→ 匯出成匯出檔（每款帶編號）→ 放在團隊共用雲端資料夾 GAE265G5 → 其他組員下載後執行同步。`games.json` 與匯出檔都不進 repo。匯入後立倫的資料庫就是正本，`games.json` 可以刪掉，GAE265G5 的匯出檔是唯一的備份。
- 「匯入桌遊」只能在 `games` 是空的時候執行；之後要新增桌遊，到時再另外設計。
- 其他組員不執行「匯入桌遊」，否則他們的資料庫會自己給號，編號就對不上。組員自己在本機新增的桌遊，下次同步會被刪掉；測試一律用寫在測試程式裡的假資料。
- 同步後，每個人的資料庫和匯出檔完全一樣：匯出檔裡沒有的桌遊會刪掉。
- 編號給出去就不改、不重複使用。匯出檔會記下資料庫的計數器（下一款要給幾號），同步時照著設定；所以不論在誰的資料庫，同步後新增的下一款都會接著往下給號，不會拿到以前用過的號碼。
- 立倫的資料庫要重建時，用 GAE265G5 最新的匯出檔同步回來，不重新匯入。GAE265G5 只放最新的一份匯出檔，每次覆蓋。
- 部署到 Azure 的正式資料庫也用同步放資料，由立倫執行，不執行「匯入桌遊」。
- 其他 domain 的表參照 `games.id` 時，**不可以**設定成「桌遊刪掉就跟著刪」。這樣同步要刪掉一款還有人在用的桌遊時，會被資料庫擋下並印出是誰在用，其他組員的資料不會被刪。
- 只有其他 domain 會用到的三張共用表要同步；推薦用的資料（心得摘要、標籤、心得片段）留在 games_advisor 自己的表，不同步，`game_id` 參照 `games.id`。心得摘要因此從桌遊表搬到 `games_advisor_review_summaries`。
- 瑋鋐審 migration 時會看到不是 UUID 的主鍵、沒有 domain 開頭的表名，MR 說明要指向本檔。
- 其他 domain 直接依賴這三張表的欄位，之後改欄位名稱或刪欄位，要先確認沒有 domain 在用。
