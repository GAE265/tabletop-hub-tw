# 手動測試：規則影片生產器的手機驗收（1d 檢查點）

> 適用變更：`add-rules-video-mobile`（MR 1–10），對應 `openspec/changes/add-rules-video-mobile/tasks.md` 的 **3.1、3.2**。
> 用瀏覽器以店員身分走完《血與刃》：選遊戲建立專案 → 自動產生草稿 → 拍素材、標區域 → 產生影片 → 看完。全程不用命令列（準備階段除外）。

> 📌 **這次（2026-11-22）用網頁端驗收**：在電腦的 Chrome 開 `localhost`，不用手機。
> - 第 1.2 節（查 IP）、第 1.4 節（防火牆）、`--host 0.0.0.0` 與 `--web-hostname 0.0.0.0` 都可以跳過；網址一律用 `localhost`。
> - **整個遊戲一支影片**（design.md D17）：建立專案只選遊戲，AI 從整本規則書分出「開局、走完一輪、獲勝方式」三格，建立後自動產生草稿；沒有「選頁與編輯文字」這一步。分支用 `feature/rules_qa-video-whole-game-page`（已包含整本範圍的後端）。
> - 手機才能驗證的三項列在第 7 節「尚未實機驗證」，**推送 MR 7、8、10 之前必須先用手機補測**。
> - **今天的合格標準（2026-11-22 永傑決定）**：從選遊戲到看到影片，在網頁上一次走完，而且**連續兩個新的整本專案都成功**（第 4 節 A～F 走兩輪，第二輪見 H）。
> - **用新的專案**：每一輪都新建專案、重新上傳素材照片；舊專案不要動（不要刪、不要重新產生）。
> - 草稿工作已加上自動補救（R0）：分類漏頁時另外補分類、每一格最多改寫 2 次、第一次沒通過檢查時**自動整個重新產生一次**。所以草稿可能要 2～4 分鐘，進度卡可能出現「第一次沒有通過檢查，自動重新產生」，這是正常的。
> 本檔只寫設定名稱與預期結果，**不要把金鑰、密碼、規則書內容貼進來**。規則書頁面已在 dev 資料庫裡，不放進 repo（AGENTS.md 2.2）。

## 1. 準備電腦（只做一次）

### 1.1 切到驗收用的分支並更新

在 repo 根目錄：

```powershell
git checkout feature/rules_qa-video-whole-game-page
cd backend
uv sync
# 先確認 DATABASE_URL 的主機是 localhost（不要對共用資料庫執行）
uv run alembic upgrade head          # 升到 0020（整本範圍：章節欄位可空、分類結果）
uv run python -m app.dev.seed        # 測試帳號（可重複執行）
cd ..\frontend
flutter pub get
dart run build_runner build --delete-conflicting-outputs
```

> ⚠️ PATH 上的 Flutter 是 3.47.6，用它跑 `flutter pub get` 會改動 `frontend/pubspec.lock`（CI 用 3.41.4）。建議改用和 CI 相同版本的 `D:\tools\flutter-3.41.4\bin\flutter`（`pub get`、`dart run build_runner`、`flutter run` 都用它），就不會改到 lock。用了 3.47.6 的話，驗收完用 `git checkout -- frontend/pubspec.lock` 還原，**不要 commit**。

### 1.2 查電腦的 IP（網頁端驗收可跳過）

```powershell
ipconfig
```

找「無線區域網路介面卡 Wi-Fi」的 **IPv4 位址**，例如 `192.168.1.23`。下面用 `<電腦IP>` 代表它。

> 路由器可能換 IP：每次驗收前重新確認，IP 變了要一起改 1.3 的 `CORS_ALLOW_ORIGINS` 和 2.2 的 `API_BASE_URL`。

### 1.3 `.env` 要調整的設定

只改下面這些欄位（**值不要貼進對話或文件**）：

| 欄位 | 驗收時的值 | 為什麼 |
|---|---|---|
| `AUTH_MODE` | `dev` | 用開發身分切換器當店員、管理員 |
| `CORS_ALLOW_ORIGINS` | 網頁端：`http://localhost:5000`；手機：再加 `,http://<電腦IP>:5000` | 前端的網址不在清單內，請求會被瀏覽器擋掉 |
| `STORAGE_PROVIDER` | `local` | **不要用 `fake`**（存在記憶體，後端一重啟照片就消失）；驗收也先不用 `cloud` |
| `STORAGE_LOCAL_DIR` | `D:/project/tabletop-hub-tw/backend/.local/storage` | 照片與成品影片存在這裡（已被 gitignore） |
| `STORAGE_PUBLIC_BASE_URL` | `http://localhost:8000/media` | `local` 必填；手機讀照片與影片都走帶身分的 API，不會用到這個網址 |
| `VIDEO_FONT_REGULAR` | `C:\Windows\Fonts\msjh.ttc` | 影片裡的中文字型（微軟正黑體）。**沒設時中文會變成方塊** |
| `VIDEO_FONT_BOLD` | `C:\Windows\Fonts\msjhbd.ttc` | 粗體 |
| `LLM_PROVIDER` 等 LLM 設定 | 照原本 | 產生草稿要用真的 LLM（整本 13 頁：約 3 次呼叫、約 1 分鐘） |
| `TTS_PROVIDER`、`TTS_REGION`、`TTS_API_KEY` | `azure` 與你的設定 | 有設才有旁白；沒設（`fake`）時旁白是靜音，畫面會註明「時間為估計值」 |
| `RULES_VIDEO_WORK_DIR` | 不用填 | 預設 `backend/.local/rules_videos` |

> 存放設定寫錯（例如 `local` 卻沒填 `STORAGE_LOCAL_DIR`）時，**後端會起不來**，終端機會寫缺哪個設定。

### 1.4 防火牆（網頁端驗收可跳過）

第一次用 `0.0.0.0` 啟動後端或前端時，Windows 會跳出「允許存取」的視窗：勾「私人網路」後按允許。沒有跳出來而手機連不上時，用系統管理員身分的 PowerShell 開放兩個埠：

```powershell
New-NetFirewallRule -DisplayName "tabletop-hub dev 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "tabletop-hub dev 5000" -Direction Inbound -Protocol TCP -LocalPort 5000 -Action Allow -Profile Private
```

並確認 Wi‑Fi 的網路設定檔是「私人」（設定 → 網路和網際網路 → Wi‑Fi → 內容）。驗收完可以在「具有進階安全性的 Windows 防火牆」刪掉這兩條規則。

## 2. 啟動

### 2.1 資料庫與後端

```powershell
docker compose up -d                 # repo 根目錄；先開 Docker Desktop
cd backend
uv run uvicorn app.main:create_app --factory --port 8000                 # 網頁端
uv run uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000  # 手機（第 7 節補測時）
```

| 預期 | 說明 |
|---|---|
| 終端機出現 `Uvicorn running on http://127.0.0.1:8000`（手機版是 `0.0.0.0`） | 後端起來了 |
| 瀏覽器開 `http://localhost:8000/api/v1/health`（手機：`http://<電腦IP>:8000/...`）看到 `{"status":"ok","database":"up"}` | 連得到後端 |

> 8000 已被別的後端占用時（例如舊版本還開著），改用 `--port 8001`，前端的 `API_BASE_URL` 與 `CORS_ALLOW_ORIGINS`（前端的網址）跟著改。

這個終端機就是**後端日誌**，驗收時保持開著（見第 5 節）。不要加 `--reload`：存檔時重啟會中斷正在跑的工作（中斷的工作會被標為失敗）。

### 2.2 前端

另開一個終端機：

```powershell
cd frontend
# 網頁端：直接開 Chrome
D:\tools\flutter-3.41.4\bin\flutter run -d chrome --web-port 5000 --dart-define=API_BASE_URL=http://localhost:8000
# 手機（第 7 節補測時）
D:\tools\flutter-3.41.4\bin\flutter run -d web-server --web-hostname 0.0.0.0 --web-port 5000 --dart-define=API_BASE_URL=http://<電腦IP>:8000
```

| 預期 | 說明 |
|---|---|
| 網頁端：Chrome 自動打開首頁；手機：出現 `lib\main.dart is being served at http://0.0.0.0:5000` | 前端起來了 |
| 手機開 `http://<電腦IP>:5000` 看到首頁 | 第一次載入比較慢（開發版），等十幾秒 |
| 畫面最上方有「開發身分」切換器 | 一定要用 `flutter run`（開發版）；release 建置沒有切換器 |

### C. 產生草稿（自動開始）

| C6 | 草稿需要改：按「重新產生」 | 再跑一次草稿工作；已拍的照片會沿用（區域名稱若變了要重標，見 D17） |

| C8 | 失敗時（例如 AI 逾時） | 進度卡只寫原因與「重試」，**不會出現**段代號（例如 `s3`、`h1`）這類內部代號 |

### 5.2 出錯時要截的畫面與要貼的文字

1. **手機畫面**：出錯當下的整個畫面，要看得到**網址列**（知道在哪一頁、哪個專案）。

### 5.3 常見狀況

| 狀況 | 原因與處理 |
|---|---|
| 手機打不開 `<電腦IP>:5000` | 不同 Wi‑Fi、訪客網路，或防火牆（1.4）；先試 `<電腦IP>:8000/api/v1/health` |
| 頁面開了但一直「無法連線」 | `API_BASE_URL` 的 IP 不對，或 `CORS_ALLOW_ORIGINS` 沒加 `http://<電腦IP>:5000`；改完重啟後端 |

| 導覽列沒有「影片」 | 身分是玩家；切成店員 |
| 建立時「這款遊戲的規則書還沒有匯入」 | 那款遊戲在 dev 資料庫沒有規則書頁面，照 3.1 匯入 |
| 草稿失敗「規則書裡找不到「獲勝方式」的內容」 | AI 分不出那一格；`manual_case_video_status.py` 看細節後給我，可能是規則書少了那幾頁 |
| 草稿失敗「AI 產生的草稿沒有通過檢查」或「規則書第 N 頁沒有分到…」 | 已經自動重試過一次仍失敗；按「重新產生」再試。連續兩次失敗就給我 5.2 的資料（`manual_case_video_status.py` 會印出兩次失敗的細節） |
| 草稿工作失敗「AI 服務暫時無法使用」 | LLM 逾時或忙碌；稍後按「重試」。一直失敗就給我 5.2 的資料 |
| 影片工作失敗「產生影片的設定有誤」 | 字型路徑或 TTS 設定錯；後端終端機會多印一行「字型設定錯誤」或「文字轉語音設定錯誤」 |
| 影片工作失敗「影片輸出失敗」 | ffmpeg 出錯；後端終端機的「產生影片失敗（專案 …）」那行有 ffmpeg 的訊息 |
| 中文變方塊 | 沒設 `VIDEO_FONT_REGULAR`／`VIDEO_FONT_BOLD`（1.3），設好重啟後端再產生 |
| 沒有旁白、畫面寫「時間為估計值」 | `TTS_PROVIDER` 是 `fake`；要旁白就設 Azure TTS 後重啟 |
| 後端重啟後照片不見 | `STORAGE_PROVIDER` 還是 `fake`；改成 `local` |
| 手機很燙、影片很久才出現 | 影片要整支下載才能播（已知限制）；用 Wi‑Fi，不要用行動網路 |
