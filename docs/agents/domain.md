# Domain 文件

mattpocock 的 engineering skills 探索程式碼時，怎麼使用本 repo 的 domain 文件。

## 探索前先讀

1. **`AGENTS.md` §10（術語表）**：團隊的正式術語表（10.1 角色、10.2 遊戲進行、10.3 揪團），優先於其他所有來源。AI 不得修改。
2. 根目錄 **`GLOSSARY.md`** 的 `## 提案中的術語` 區塊：已經提出、但還沒收進 §10 的術語，一律視為暫定。
3. **`docs/adr/`**：讀跟你要處理的範圍有關的 ADR。

`docs/adr/` 不存在時，**直接繼續，不用特別提出**，也不要建議先建立。`/domain-modeling` skill（經由 `/grill-with-docs` 與 `/improve-codebase-architecture` 帶入）會在真的有決策要記錄時才建立它。

## 檔案結構

本 repo 是 single-context：

```
/
├── AGENTS.md        ← §10 正式術語表（AI 只能讀）
├── GLOSSARY.md      ← 指向 §10 的指標，以及提案中的術語
└── docs/adr/
    ├── 0001-<slug>.md
    └── 0002-<slug>.md
```

## 使用術語表的用詞

輸出內容提到 domain 概念時（issue 標題、重構提案、假設、測試名稱），一律用 `AGENTS.md` §10 定義的用詞；程式命名用 §10 的英文欄。不要換成同義詞。

§10 與提案區都找不到這個概念時，代表兩種情況之一：你在發明專案沒在用的說法（請重新考慮），或是真的有缺口。新詞**只能**寫進 `GLOSSARY.md` 的 `## 提案中的術語` 區塊。組員同意後，由組員把術語搬進 §10，再從 `GLOSSARY.md` 刪除；AI 不做這個搬移。

## 標出與 ADR 的衝突

輸出內容與既有 ADR 矛盾時，要明確指出，不要默默推翻：

> _與 ADR-0007（<決策標題>）矛盾，但值得重新討論，因為……_
