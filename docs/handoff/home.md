# 設計說明：首頁（home）

> Demo 給評審看的首頁。所有角色看到同一個畫面，不分角色。
> 設計稿（手機版＋桌機版）：https://claude.ai/artifact/S9Bz8X4Fn7ttbDQT4dzVip
> 首頁不屬於 AGENTS.md 第 3 節的任何 domain，放置位置待討論（見第 6 節）。

## 1. 現況與目標

- 現況：路由 `/` 掛的是 `HealthPage`（後端健康檢查示範頁），`app/shell.dart` 的 `_TemporaryNav` 是暫時的頂部導覽。
- 目標：`/` 換成真正的首頁；用底部導覽列（手機）與頂部導覽列（桌機）取代 `_TemporaryNav`。
- 首頁只負責把人最快送到下一步，不是功能展示櫃。

## 2. 頁面內容（由上到下）

| 區塊 | 內容 | 備註 |
|---|---|---|
| 頂部 | 品牌名「遊任有娛」、登入圖示按鈕 | 登入功能屬於 `auth`（階段 3），目前按鈕可先不接 |
| 主標 | 「今天想怎麼玩？」＋副標「找遊戲、揪人、訂位、學規則，一個地方搞定。」 | |
| 入口卡片 ×4 | 見下表 | 手機 2×2，桌機一橫列 4 張，窄螢幕自動換行 |
| 接下來的行程 | 我即將到來的訂位與已報名的揪團，各以一列呈現 | 需要的資料見第 4 節 |
| 導覽列 | 首頁、揪團、推薦、規則、訂位 | 手機在底部、桌機在頂部；目前頁面要有選取樣式 |

入口卡片：

| 標題 | 說明文字 | 導向路由 |
|---|---|---|
| 今天玩什麼？ | 跟助理聊聊，幫你挑遊戲 | `/games-advisor` |
| 找人一起玩 | 開團或加入，額滿可候補 | `/groups` |
| 訂個位子 | 挑桌遊店，直接選座位 | `/booking` |
| 這遊戲怎麼玩 | 看教學、隨時問規則 | `/rules` |

## 3. 狀態顯示

| 狀態 | 要顯示什麼 |
|---|---|
| 載入中（行程區） | 骨架或載入指示，其他區塊照常顯示 |
| 沒有資料（行程區） | 空狀態，引導去「找人一起玩」或「訂個位子」，不要留白 |
| 錯誤（行程區） | 錯誤訊息與重試，不影響入口卡片 |

## 4. 資料來源（待確認）

「接下來的行程」要同時取得訂位與揪團資料。依 AGENTS.md 4.2，domain 之間只能呼叫對方的 `service`。

- 需先確認現有 API 是否足夠：我的訂位（現有 `/booking/mine` 頁面用的資料）、我已加入的揪團。
- 若不夠，先回報，不要自行修改後端。

## 5. 不放的內容

- 戰績與天梯：功能尚未完成。
- 健康狀態：僅供開發使用。
- 角色分流（店家人員專屬首頁）：Demo 版先不做。

## 6. 待討論

- 首頁的程式放哪裡（`frontend/lib/app/`、`frontend/lib/domains/home/`，或其他）？
- 顏色、字級、間距一律用 `app/theme/`，頁面不寫死數值。
- 設計稿是示意：店家名稱 `[店家名稱]`、《阿瓦隆》、日期與人數都是示範資料，不是真實資料。
- 底部／頂部導覽列完成後，刪除 `shell.dart` 的 `_TemporaryNav`。
