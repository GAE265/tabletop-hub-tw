# 玩家怎麼和主持人說話

Type: grilling
Status: resolved
Blocked by: 01, 05, 07
Map: [AI 語音主持](../map.md)

## Question

全桌玩家共用桌上一台手機或平板的麥克風。玩家會邊玩邊聊天、說「嗯」，主持人不能每句都接話。試聽與補測的結果寫在 Comments，依它們決定：

1. 接話方式：自動接話（`smart_turn_v2`），還是按住頁面上的按鍵才說話。
   - 另一種自動接話 `server_vad` 已經可以排除：桌邊閒聊 6 句，它回了 5 句、被打斷 4 次，調靈敏度也沒用。
   - `smart_turn_v2`：桌邊閒聊 6 句都沒回，外放時也沒有聽到自己的聲音而打斷自己。但玩家說「等一下」，它不會停。
   - 這個設定只能在連線一開始決定，同一條連線不能中途切換。
2. 語音指令怎麼確實生效。2026-11-20 需求變更：下面這些一定要支援，用工具呼叫送到後端處理，不再是選項。
   - 「等一下」「暫停」：同一個動作，主持人停下來。
   - 「下一步」「上一步」：換階段、退回。頁面已定有這兩顆按鍵。
   - 「結束了」「某一方贏了」：兩種說法都可以結束這場主持。

   已知的事實：`smart_turn_v2` 下，主持人正在說話時玩家說「等一下」，5 次都被判定成不是在跟它說話。模型不回應，也就不會自己呼叫工具。但那段話仍有語音辨識文字。

   要決定：
   - 由誰觸發：模型自己呼叫工具、後端看語音辨識的文字、或兩種都做。五個指令可以不一樣。
   - 「暫停」「結束」要不要也在頁面放按鍵當保底。
   - 閒聊裡剛好講到這些字（例如「等一下再出牌」）時，會不會誤觸發，怎麼避免。
3. 暫停之後。
   - 暫停時主持人要不要回一句。
   - 暫停中還聽不聽、回不回答規則問題。
   - 怎麼恢復：說「繼續」、按鍵、或說「下一步」。
   - 恢復後要不要把被打斷的那段接著講（要由後端保留那一段）。補測時說「繼續」，主持人會自己編新內容，還會自己把流程往前推。
4. 玩家說台語或其他語言時，主持人怎麼回應。
5. 螢幕鎖住或切到別的 App 之後，收音和播音不保證還能運作。要不要讓頁面保持螢幕常亮；被切走再回來時怎麼處理。
6. 開主持時用哪個聲線：固定一個，還是讓玩家在頁面選。試聽選了 `xunanchuan_v3.1`（男聲）與 `longyuan_v3.1`（女聲）。一條連線開了之後就不能換聲線。

## Answer

2026-11-21 立倫決定。量到的數字都是小測，細節在 Comments。

### 1. 接話方式

- **兩種都做**：自動接話（`smart_turn_v2`，預設）與按住說話。`server_vad` 不用。
- 自動接話的靈敏度（`threshold`）用預設的 0.5，不設 `silence_duration_ms`。依據：調到 0.8 擋不住閒聊；`silence_duration_ms` 在 `smart_turn_v2` 無效。
- 開主持前在頁面選。主持中也可以切換：手機用新的接話方式重新連線，同一場主持接著走，回合與階段都在（走「接著主持」同一條路）。
- 按住說話：按下去主持人立刻停，放開後主持人才回答。按住時說語音指令一樣有效，過同一道核對。
- 理由：自動接話擋不擋得住桌邊閒聊，證據互相矛盾。「[用真的聲音試聽 Qwen 主持人](07-listen-to-qwen-host.md)」喇叭外放 6 句都沒回；這張用合成語音直接餵，幾乎每句都被當成在跟它說話。按住說話是唯一確定不受閒聊影響的方式，當退路。

### 2. 語音指令

- 清單（起點；完整清單與可接受的寫法在 spec 定）：

  | 動作 | 說法 |
  |---|---|
  | 暫停 | 「等一下」「暫停」 |
  | 繼續 | 「繼續」 |
  | 下一步 | 「下一步」 |
  | 上一步 | 「上一步」 |
  | 結束 | 「結束了」「白薔薇贏了」「血刃贏了」 |

- **兩條路都開，都要過同一道核對**：
  - 路 1：模型聽懂了，呼叫工具。
  - 路 2：後端自己看辨識文字，包含片段辨識文字。
  - 核對：整句去掉標點、轉成繁體後，就是清單上的說法。前面可以加「主持人」。問句不算。容許同音字（例如「上一部」）。
  - 核對沒過：流程不動，後端告訴模型這不是指令，主持人不出聲。
  - 同一句話兩條路都看到時，只執行一次。怎麼判斷是同一句，在 spec 定。
- 例子：「主持人，下一步」會換階段；「你下一步要出什麼」「白薔薇贏了嗎」「暫停一下，我去上廁所」都不動。
- 「等一下」主要靠路 2：主持人說話時模型聽不到它（12／12 不算一句），但片段辨識文字在說完 0.15 秒內就有整句。
- 每個動作都有按鍵：下一步、上一步、暫停／繼續（同一顆，這張新增）、結束主持。頁面列出可以說的指令。
- 結束：說「結束了」或某一方贏了，不再確認，主持人直接唸結束台詞。結束後 30 分鐘內，頁面可以「接著主持」回到原本的回合與階段。

### 3. 主持暫停與繼續

- 進入主持暫停：說「等一下」「暫停」、按暫停鍵、頁面被切走或鎖屏。
- 暫停時主持人馬上停，不回話。頁面顯示「主持暫停中」。
- 暫停中主持人不自己往下走（例如夜晚的倒數會停）。玩家問規則時照常回答，答完還是暫停中。
- 繼續：說「繼續」或按鍵。主持人把被打斷的那一段從頭重講。那一段可能是階段的規則要點、固定台詞、夜晚的口令與倒數，或規則問題的回答。沒有被打斷的段落時，只說「回到第 N 回合的某階段」。
- 暫停中說「下一步」「上一步」或按鍵：直接照做，暫停解除，被打斷的那一段作廢。
- 重講的內容由後端重新交給主持人，不靠模型自己記。不做「從斷掉的那個字接下去」。依據：補測時讓模型自己接，它會編新內容，還會自己把流程往前推。
- 主持人被玩家的問題打斷時：答完只補一句「回到第 N 回合的某階段」（「[主持人在一局裡怎麼帶流程](08-host-flow-in-a-match.md)」已定），不自動重講；玩家說「繼續」才重講。
- 按住說話時被按鍵打斷的那一段，同樣是說「繼續」或按鍵才重講。

### 4. 閒聊

- 模型多一個「不回應」工具：聽到的話不是在問它、也不是語音指令，就呼叫這個工具，不出聲。後端收到後不請主持人回答。
- 主持人被閒聊切斷時（有人一開口，伺服器就取消正在產生的回答，查不到可以關掉的設定）：後端自動請主持人把那一段重講，玩家不用說「繼續」。後端收到「不回應」工具的呼叫，或那句話被判定成不是在跟它說話，就知道是閒聊。
- 同一段最多自動重講 2 次，再被切斷就進入主持暫停。「2 次」是提議，沒有實測。
- 有人說話時，主持人不降音量、不先停。只有語音指令和對它說的話才會讓它停。
- 含指令字的閒聊，模型仍然會誤呼叫指令工具（12 句 7 次），由第 2 節的核對擋下。

### 5. 語言、螢幕、聲線

- **語言**：主持人只用中文。不替其他語言寫任何規則，spec 記成「只支援中文」。
- **螢幕**：
  - 主持進行中，頁面要求螢幕常亮（包在 `core/platform/` 的介面後面，AGENTS.md §5.3）。
  - 系統拒絕常亮時（例如低電量），頁面顯示一行「請關掉自動鎖定」，不擋主持。
  - 頁面被切走或鎖屏：手機立刻停止收音與播音，這場主持進入主持暫停。
  - 回到頁面：顯示「點一下繼續」，點了才繼續。
  - 離開太久、連線斷了：照「[主持人在一局裡怎麼帶流程](08-host-flow-in-a-match.md)」的 30 分鐘保留，重開頁面選「接著主持」。
- **聲線**：
  - 開主持前從兩個選一個：男聲 `xunanchuan_v3.1`（預設）、女聲 `longyuan_v3.1`。
  - 開始後這場主持不能換。「接著主持」與切換接話方式都沿用原本的，要換就「重新開始」。
  - 手機只送我們自己定的代號（名稱在 spec 定），後端再對應到阿里雲的聲線名稱。依據：「[聲音怎麼從瀏覽器連到模型](12-audio-connection-path.md)」已定手機不知道任何阿里雲設定。

### 沒有測過

- 真人、多人在桌邊閒聊；很吵的場地；手機外放；關掉回音消除。實作時用手動檢查量。
- 這張的速度數字來自合成語音，被當成一句的判定比真人慢（說完後 1.4 到 2.5 秒，真人是 0.2 到 0.5 秒），不能當門檻。
- 「不回應」工具只測了 45 句合成語音。
