# 三個 Agent 框架怎麼接 Qwen、怎麼展示

Type: research
Status: open
Map: [AI 語音主持](../map.md)

## Question

立倫為了展示，一定要用 Agent 框架，三選一：LangChain、LangGraph、Microsoft Agent Framework。展示重點是「看得到主持人走到哪個階段、查了什麼資料」。比較三個框架，讓立倫能選。選型查核報告（路徑見地圖 Notes）第 02 節已有一張比較表，逐項回查一手來源。

每個框架回答：

1. 能不能接 Qwen 的文字模型：官方或社群的整合套件名稱、版本、維護狀況。
2. 能不能接即時語音模型（Qwen 或其他）：有沒有內建支援；沒有的話，框架通常放在哪一段（例如只處理即時語音模型轉交過來的工具請求）。
3. 記住「這一局走到哪個階段」的做法：狀態怎麼定義、能不能暫停後再接續、狀態存在哪裡。
4. 展示手段：能不能畫出流程圖、能不能看到每一步查了什麼。哪些功能要另外付費或註冊服務（例如 LangSmith、Foundry），哪些在本機免費就看得到。
5. 和本專案規則合不合：
   - 資料庫存取一律同步寫法（AGENTS.md §4.4）。框架是否強制 async。
   - 測試替身一律手寫 fake、不用 mock 套件（AGENTS.md §7.5）。框架有沒有官方的假模型可以參考。
   - 外部服務要包在 `integrations/` 後面（AGENTS.md §4.2）。框架的程式放得進這個分層嗎。
6. 代價：會多裝哪些套件、授權、Python 3.13 支援、版本穩定度（正式版或預覽版）。

最後給一張三欄比較表，並寫出「如果展示重點是看得到階段與查詢過程」各自的優缺點。不替立倫做決定。

只用官方文件、官方 repo、PyPI 等一手來源，每項附連結、查核日期與版本。

結果寫在 `.scratch/host/research/agent-frameworks-fit.md`。
