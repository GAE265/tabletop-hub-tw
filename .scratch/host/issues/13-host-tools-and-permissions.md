# 主持人能查哪些資料、誰能開主持

Type: grilling
Status: open
Blocked by: 08, 16
Map: [AI 語音主持](../map.md)

## Question

主持人首版只讀資料（2026-11-19 畫地圖時決定）。規則問題用 `rules_qa`（永傑主責）已有的規則檢索；局況來自 `matches`（新善主責）。domain 之間只能呼叫對方的 `service`（AGENTS.md §4.2）。依主持流程，決定：

1. 主持人有哪些查詢工具：每個工具的名稱、參數、回傳什麼。選型查核報告建議只開 3 到 5 個、範圍越窄越好，待確認。
2. 查規則：`rules_qa` 的 `service` 現在提供的方法夠不夠用（它的問答會自己呼叫 LLM 回答，主持人可能只需要規則片段）。不夠的話，要請永傑新增什麼。
3. 查局況：`matches` 的 `service` 現在提供的方法夠不夠用。不夠的話，要請新善新增什麼。
4. 誰能開主持、誰能和主持人說話：三種角色都可以，還是只有這一局的參加者或開局者。沒有權限時回什麼。
5. 主持人查到的資料哪些不能說出口（對照主持流程裡的隱藏資訊）。
6. 查不到規則或資料時，主持人怎麼回答。
7. 本機的白薔薇規則全文有雜訊與錯字，圖片上的字（獲勝門檻、魔法之書的清單）沒有入庫。主持人帶流程一定會用到的數字與效果，要另外放在哪裡（例如寫在 host 自己的遊戲定義裡），還是等規則全文修好。

  - 規則題幾乎都會先查。`topic` 都選得合理；`question` 會帶進語音辨識的錯字，例如「血之陣營」。所以工具不能只靠 `question` 的字面比對。

  - 等待中玩家又問別的：不加指令時，模型先用猜的回答還在查的那題；加了「先說還在查」之後不亂猜了，但新問的那題被丟掉。等待中怎麼處理追問，要和工具的逾時一起決定。
