# 選哪個 Agent 框架、它負責什麼

Type: grilling
Status: open
Blocked by: 03, 09, 13
Map: [AI 語音主持](../map.md)

## Question

立倫為了展示，一定要用 Agent 框架，三選一：LangChain、LangGraph、Microsoft Agent Framework（2026-11-19 畫地圖時決定）。展示重點是「看得到主持人走到哪個階段、查了什麼資料」。

已經定案、這張不用再問的前提：

- 三個框架都沒有能直接接 Qwen 即時語音的官方轉接器，聲音這條路不經過框架。框架能放的位置，是後端收到語音模型的工具請求之後的那一段。
- 聲音經後端轉送，轉送那一段用非同步寫（「[聲音怎麼從瀏覽器連到模型](12-audio-connection-path.md)」）。
- 走到哪個階段由後端記，放在記憶體，不建資料表（「[主持人在一局裡怎麼帶流程](08-host-flow-in-a-match.md)」）。
- 思考模型一律透過 `integrations/llm` 呼叫，框架不能直接連 Azure（「[用 Flash 還是 Plus、要不要轉交思考模型](09-model-lineup.md)」）。

決定：

1. 用哪一個框架。
2. 框架負責哪幾段，哪些明確不交給框架。候選有四段：
   - 階段狀態：人數、第幾回合、哪個階段、圓版放了幾顆水晶；下一步、上一步、結束主持；頁面關掉後保留 30 分鐘。重連時交給主持人的前情，也是這一份。
   - 處理查規則的請求。做法照「[主持人能查哪些資料、誰能開主持](13-host-tools-and-permissions.md)」的答案。
   - 呼叫思考模型，以及等待的規則（第 8 秒補一句、15 秒放棄、新問題取代舊題）。
   - 連線的維持與重連。預設做法列在「[寫 spec.md](21-write-spec.md)」。

   連帶要答的兩件事：
   - 如果框架裡沒有任何 LLM、只是把步驟排成流程，這樣還符不符合立倫想展示的內容。
   - 工具迴圈由誰控制。專案現在的做法是 `service` 自己管迴圈、整合層一次只呼叫 1 次模型。LangChain 與 Microsoft Agent Framework 的 Agent 會自己管迴圈，LangGraph 可以只排一次工具處理。要不要為了框架改這個做法。
3. 展示時給人看什麼：流程圖、每一步的查詢紀錄，或其他。三個框架都能在本機輸出，不用另外註冊付費服務。
4. 框架的程式放在哪一層（AGENTS.md §4.2）。選 Microsoft Agent Framework 時，它的 Python 寫法是非同步的，可以放在轉送的非同步那一側；碰資料庫的部分仍要照 §4.4 用同步寫法。
5. 要不要先做一個小試跑，再寫進 spec。三個框架都只查過文件，沒有執行過。另一個做法是不試跑，把「框架骨架」排成第一張實作 ticket。

結案時要留下兩樣東西：

- 新增套件的理由（AGENTS.md §2 第 4 點），之後寫進 MR 說明。
- 一份 ADR。「用 Flash 還是 Plus、要不要轉交思考模型」已決定要寫，內容有三段：即時語音為什麼不走 `integrations/llm` 的介面、為什麼經後端轉送而不直連、為什麼用這個框架。寫好後由立倫 @ 瑋鋐，請組員同意。

研究的結論是三個框架都放得進「處理工具請求」那一段，不算接不上。之後才發現接不上時，停下來問立倫，不自行改成不用框架。

## Comments

- 2026-11-19：「[三個 Agent 框架怎麼接 Qwen、怎麼展示](03-agent-frameworks-fit.md)」已結案，細節與三欄比較表在[結果檔](../research/agent-frameworks-fit.md)。和這張有關的事實：
  - 版本：LangChain 1.5.2、LangGraph 1.2.22、Microsoft Agent Framework 1.26.0。核心都是正式版、MIT 授權。Microsoft 的 DevUI 還是預覽版。
  - 三個都能接 Qwen 的文字模型。LangChain 的 Agent 底層就是 LangGraph。
  - 展示：三個都能在本機輸出流程圖與每一步的事件，不用另外註冊付費服務。LangSmith、Foundry 是選用的。
  - LangChain：有現成的 Agent，接工具最快；但預設的「模型、工具、模型」迴圈不會自己長成遊戲的階段，要另外定義。
  - LangGraph：可以把主持的步驟直接畫成節點，流程圖和實際執行的路徑最好對照；但狀態、節點、儲存都要自己定義。
  - Microsoft Agent Framework：本機就有畫圖與 DevUI，不必改用 .NET 或搬到 Foundry；Python 寫法是非同步的。
  - 研究沒有替立倫選，也沒有沿用選型報告的排名。
- 2026-11-19：「[用 Flash 還是 Plus、要不要轉交思考模型](09-model-lineup.md)」已結案：語音用 Flash；難題由語音模型自己用工具呼叫轉交「思考模型」，預設 Azure `gpt-5.6-luna`，透過 `integrations/llm` 呼叫，不接 Qwen 文字模型。所以框架如果要負責呼叫思考模型，也要經過 `integrations/llm`，不能直接連 Azure；等待台詞、第 8 秒補話、15 秒放棄、新問題取代舊題的規則寫在那張的 Answer，框架放在這段時要能做到。
- 2026-11-20：「[主持人在一局裡怎麼帶流程](08-host-flow-in-a-match.md)」已結案。第 2 題的「走到哪個階段」已定由後端記，不交給主持人自己記。要在這張決定放在框架的狀態，還是一般程式：
  - 狀態內容：人數、第幾回合、哪個階段（開場、開局準備、夜晚、回合裡的三個階段、結束）、圓版放了幾顆水晶。
  - 動作：下一步、上一步（按鍵或主持人呼叫工具）、結束主持；放最後一顆水晶的回合要觸發兩句提醒。
  - 保留：頁面關掉後在記憶體保留 30 分鐘，可以接著主持。不掛戰績的局，不讀 `matches`。
  - 展示重點「看得到主持人走到哪個階段」就是這份狀態。
- 2026-11-20：「[聲音怎麼從瀏覽器連到模型](12-audio-connection-path.md)」已結案：走經後端轉送。轉送那一段用非同步寫，查規則與思考模型丟到另一條執行緒跑同步程式。框架放在「後端收到工具請求之後」那一段；選 Microsoft Agent Framework（非同步）時，可以直接放在轉送的非同步那側，但碰資料庫的部分仍要照同步寫法。
