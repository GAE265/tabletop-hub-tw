# 選哪個 Agent 框架、它負責什麼

Type: grilling
Status: resolved
Blocked by: 03, 09, 13, 23
Map: [AI 語音主持](../map.md)

## Question

立倫為了展示，一定要用 Agent 框架。展示重點是「看得到主持人走到哪個階段、查了什麼資料」。

2026-11-20 需求變更：**LangGraph 當首選**。這張先驗證 LangGraph 做不做得到下面兩個新需求。做不到，才回頭看 LangChain 與 Microsoft Agent Framework。原本的「三選一」不再逐一比較。

- **整局記憶**：主持人整局都要照規則說話，但語音模型記得的有限。對話歷史預設 20 輪、最多 50 輪，歷史音訊最多 300 秒；180 秒沒回答會斷線，重連後是一段新的對話。所以要記的事得放在語音模型以外的地方，再交回給它。
- **語音指令**：「等一下」「暫停」（同一個動作）、「下一步」、「上一步」、「結束了」「某一方贏了」（兩種說法都可以結束），用工具呼叫送到後端處理。

已經定案、這張不用再問的前提：

- 三個框架都沒有能直接接 Qwen 即時語音的官方轉接器，聲音這條路不經過框架。框架在後端。
- 聲音經後端轉送，轉送那一段用非同步寫（「[聲音怎麼從瀏覽器連到模型](12-audio-connection-path.md)」）。
- 一場主持的狀態放在記憶體，不建資料表，頁面關掉後保留 30 分鐘（「[主持人在一局裡怎麼帶流程](08-host-flow-in-a-match.md)」）。
- 思考模型一律透過 `integrations/llm` 呼叫，框架不能直接連 Azure（「[用 Flash 還是 Plus、要不要轉交思考模型](09-model-lineup.md)」）。
- 每個階段開始時，後端把那個階段的規則要點交給主持人，主持人照著說（需求變更，更正了「主持人在一局裡怎麼帶流程」的「自由說」）。規則要點從哪裡來，在「[寫 spec.md](21-write-spec.md)」寫 spec 時一起定（要參考「[主持人能查哪些資料、誰能開主持](13-host-tools-and-permissions.md)」第 1 題的答案）；有哪幾條，由「[白薔薇 demo 的主持規則：追加哪些、忽略哪些](23-white-rose-demo-host-rules.md)」決定。

決定：

1. LangGraph 做不做得到整局記憶、語音指令的處理、展示。有做不到的部分時，是哪一部分，要不要改看另外兩個框架。
2. 整局記憶記什麼。
   - 已知要記的：人數、第幾回合、哪個階段、圓版放了幾顆水晶、是不是暫停中。
   - 要決定記不記的：玩家問過的規則問題與答案、玩家說哪一方贏、被打斷沒講完的那段話。
   - 不記的：隱藏資訊（「主持人在一局裡怎麼帶流程」已定）。
3. 記憶怎麼交回給語音模型。
   - 什麼時候交：換階段、重連、每隔一段時間。
   - 交多少：全部，或只交摘要。
   - 誰組出那段文字：程式照狀態組，或另外用文字模型做摘要。
4. LangGraph 負責哪幾段，哪些明確不交給它。候選有五段：
   - 階段狀態與語音指令：下一步、上一步、暫停與恢復、結束主持；頁面關掉後保留 30 分鐘。
   - 整局記憶（第 2、3 題）。
   - 處理查規則的請求。做法照「[主持人能查哪些資料、誰能開主持](13-host-tools-and-permissions.md)」的答案。
   - 呼叫思考模型，以及等待的規則（第 8 秒補一句、15 秒放棄、新問題取代舊題）。
   - 連線的維持與重連。預設做法列在「[寫 spec.md](21-write-spec.md)」。

   連帶要答的兩件事：
   - 如果框架裡沒有任何 LLM、只是把步驟排成流程，這樣還符不符合立倫想展示的內容。
   - 工具迴圈由誰控制。專案現在的做法是 `service` 自己管迴圈、整合層一次只呼叫 1 次模型。LangChain 與 Microsoft Agent Framework 的 Agent 會自己管迴圈，LangGraph 可以只排一次工具處理。要不要為了框架改這個做法。
5. 展示時給人看什麼：流程圖、每一步的查詢紀錄、整局記憶的內容，或其他。LangGraph 能在本機輸出，不用另外註冊付費服務。
6. 框架的程式放在哪一層（AGENTS.md §4.2）。轉送那一段是非同步的；碰資料庫的部分仍要照 §4.4 用同步寫法。
7. 要不要先做一個小試跑，再寫進 spec。LangGraph 只查過文件，沒有執行過。另一個做法是不試跑，把「框架骨架」排成第一張實作 ticket。

結案時要留下兩樣東西：

- 新增套件的理由（AGENTS.md §2 第 4 點），之後寫進 MR 說明。
- 一份 ADR。「用 Flash 還是 Plus、要不要轉交思考模型」已決定要寫，內容有三段：即時語音為什麼不走 `integrations/llm` 的介面、為什麼經後端轉送而不直連、為什麼用這個框架。寫好後由立倫 @ 瑋鋐，請組員同意。

研究的結論是三個框架都放得進「處理工具請求」那一段，不算接不上。整局記憶這個新需求，研究當時沒有查。之後才發現 LangGraph 做不到時，停下來問立倫，不自行改成別的框架，也不自行改成不用框架。

## Answer

2026-11-21 立倫決定。

### 1. 用 LangGraph

- 用 LangGraph，不回頭看 LangChain 與 Microsoft Agent Framework。
- 寫法是「**每件事跑一次圖**」：一個語音指令、一次按鍵、一個查規則的請求，各跑一次圖。記憶留在圖的儲存裡，下一件事進來時接著用。
- 不用「圖停在階段節點等下一個指令」的寫法。試跑時，中途記下暫停之後流程接不回去；暫停與查規則都不是換階段。
- 代價：流程圖畫的是「後端怎麼處理一件事」，不是遊戲的階段。走到哪個階段，從整局記憶讀。
- 依據是一個小試跑（`langgraph` 1.2.22、Python 3.13、假的流程、不叫模型），結果在 Comments。腳本不留，也不排進實作 ticket。
- 沒有試過的：計時、同一場主持同時來兩件事、和真的語音連線接在一起。這三項都在圖的外面，由 spec 的情境表格與實作的測試涵蓋。

### 2. LangGraph 負責哪幾段

| 段落 | 交給 LangGraph | 說明 |
|---|---|---|
| 核對語音指令、換階段、暫停與繼續、結束 | 是 | 包含「這不是指令」的出口 |
| 整局記憶 | 是 | 一場主持一份，用 LangGraph 內建的記憶體儲存，不建資料表 |
| 查規則 | 是 | 一個節點，呼叫 `rules_qa` 的只檢索方法 |
| 呼叫思考模型 | 是 | 一個節點，經過 `integrations/llm` |
| 等待的計時（第 8 秒補話、15 秒放棄、新題取代舊題） | 否 | 屬於轉送那一段的程式 |
| 連線的維持與重連 | 否 | 屬於轉送那一段。重連後向圖要「該交回什麼」 |
| 30 分鐘後清掉、一人一場、權限 | 否 | `host` 的 `service` |

- 圖裡只有「思考模型」節點會叫 LLM，其他節點都是照規則跑的程式。帶流程由程式決定，不由 LLM 決定。立倫接受這樣仍算用了 Agent 框架。
- 工具迴圈不改：語音模型自己決定要不要呼叫工具，圖一次只處理一個請求。`service` 管迴圈、整合層一次只呼叫 1 次模型的做法維持原樣。

### 3. 整局記憶記什麼

- 人數、第幾回合、哪個階段、是不是主持暫停中、接話方式、聲線、被打斷的那一段、同一段已經自動重講幾次、這場主持是不是已結束。
- 玩家說哪一方贏：要記。
- 玩家問過的規則問題：記最近 5 題的問題、查到哪幾段原文（頁碼）。不記主持人回答的文字，重連後也不把舊的問答交回給主持人。理由：規則問題已定一律先查，主持人忘了答過什麼也不會答錯。
- 圓版放了幾顆水晶不另外記，它等於回合數。
- 不記：隱藏資訊、翻牌結果、金幣與水晶在誰手上（已定）。

### 4. 記憶怎麼交回給語音模型

| 什麼時候 | 交什麼 |
|---|---|
| 開主持、每次重新連線（含切換接話方式、接著主持） | 完整指令，加上現況：第幾回合、哪個階段、是不是主持暫停中 |
| 換階段、上一步、繼續、自動重講 | 那個階段的規則要點或固定台詞（已定） |
| 每 150 秒那則不出聲的系統訊息 | 順便帶一句現況 |

- 文字全部由程式照整局記憶組出來，不另外叫文字模型做摘要。
- 重新連線後不重講那個階段，主持人只說一句「回到第 N 回合的某階段」。玩家說「繼續」才重講。
- 第三列沒有實測過（那則訊息帶現況後，主持人會不會開口、算不算進 50 輪）。列進手動檢查。

### 5. 展示

- **不做展示頁，後端不另外開端點。** 查到規則書的哪幾頁、整局記憶的內容、每一步的紀錄，都不顯示。理由（立倫）：重點是語音。
- 展示就是主持頁面本身：第幾回合、走到哪個階段、正在查規則。
- demo 時用筆電開網頁，不是手機。
- 流程圖（LangGraph 輸出的 Mermaid 文字）輸出一次，放進文件與簡報。不註冊 LangSmith，不開它的追蹤。
- 頁面的設計稿（參考用，不是定案）在 [`prototypes/ui-mockups/v1/`](../prototypes/ui-mockups/v1/)，寫 spec 的參考畫面時用。

### 6. 程式放哪一層

- 圖放在 `backend/app/domains/host/`，是那個資料夾裡的一個新檔案，由 `service` 呼叫。不放 `integrations/`：LangGraph 不連外部服務，而且圖知道白薔薇的階段，`integrations/` 不能知道任何 domain 的事（AGENTS.md §4.2）。
- 圖往外只走兩條路：查規則找 `rules_qa` 的 `service`；思考模型走 `integrations/llm`。
- 只加 `langgraph` 一個套件。不用 LangChain 的模型包裝（`ChatQwen`、`ChatOpenAI`）。
- 圖是同步的，轉送那一側用另一條執行緒跑它。同一場主持一次只處理一件事，其他的排隊。
- 測試：圖跑真的，查規則與思考模型換成手寫的 fake（AGENTS.md §7.5）。
- AGENTS.md §4.1 的目錄只列五種檔名，多一個檔案寫進 ADR 讓組員看到。

### 7. 新增套件的理由（之後貼進 MR 說明）

> 新增 `langgraph`（MIT，正式版）。用途：把主持的流程（核對語音指令、換階段、查規則、轉交思考模型）排成一張圖，並保存一場主持的整局記憶。選它的原因：展示要看得到主持人走到哪個階段、查了什麼資料，它能直接輸出流程圖與每一步的紀錄。它不連任何外部服務；會連帶安裝 16 個套件，其中 `langsmith` 的追蹤功能不開。

- 版本寫 `langgraph>=1.2.22,<2`。在 `backend/pyproject.toml` 的暫存副本試過解析：成功，多 17 個套件（含 `langgraph`），現有套件的版本都沒變，解析到 1.2.24。
- 展示改成不顯示查詢紀錄之後，這段的「每一步的紀錄」只剩後端紀錄會用到。貼進 MR 說明前由立倫決定要不要改寫。

### 8. ADR

- 草稿：[`docs/adr/0004-host-realtime-voice-and-langgraph.md`](../../../docs/adr/0004-host-realtime-voice-and-langgraph.md)，`status: proposed`。四段：即時語音不走 `integrations/llm` 現有的介面、經後端轉送、用 LangGraph 與它管哪幾段、帶流程由程式決定（和 ADR 0002 相反）。
- 立倫看過後，由立倫 @ 瑋鋐請組員同意。

### 用詞

- 沒有新增術語。
