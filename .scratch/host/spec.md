## 1. 整體

```
手機或筆電的網頁 ──聲音＋按鍵──► 後端 ──聲音──► 阿里雲即時語音模型（主持人的聲音）
        ◄──聲音＋現況──         │  ◄──聲音、辨識文字、工具請求──
                                │
                                ├─ 圖（LangGraph）：核對語音指令、換階段、整局記憶
                                ├─ rules_qa：查規則原文片段
                                └─ integrations/llm：思考模型
```

- 聲音經後端轉送，瀏覽器不直連阿里雲（D12 §1）。WebRTC 直連只記為備案。
- 語音模型：`Qwen-Audio-3.1-Realtime` Flash，新加坡區（D09 §1、D14）。備案只記一行：Azure `gpt-realtime-2.1`，或「語音轉文字 → 文字模型 → 文字轉語音」（D09 §6）。
- 帶流程由程式決定，不由 LLM 決定。語音模型負責聽、說、決定要不要呼叫工具（D10 §2、ADR 0004）。
- 主持不存資料：不建資料表，不存對話與錄音（預設 10）。一場主持的內容只在後端記憶體。
- 首版後端固定一台（D12 §8）。
- 只支援中文（D11 §5）。只做《血與刃的白薔薇》一款。
- 阿里雲會保留推論資料最多 30 天，已接受，頁面不另外告知；測試與 demo 只用組員的聲音（D14）。

## 2. 一場主持

### 2.1 內容與存活

一場主持由一位使用者開，內容就是整局記憶（第 9 節）。

- 開主持要給三樣：人數（5 到 10）、接話方式、聲線（D08 §1、D11 §1、§5）。
- 不掛戰績的局，不讀 `matches`（D08 §1）。
- 一個人同一時間只有一場。再開一場，舊的那場直接清掉，不回 409（D13 §5）。
- 同一場主持同一時間只連一支裝置。後連上的取代先連的（D13 §5）。
- 狀態有兩種：進行中（`active`）、已結束（`ended`）。主持暫停不是狀態，是進行中的一個標記（D10 Comments）。
- **「新」** 清掉的時機：沒有任何裝置連著滿 30 分鐘，或已結束滿 30 分鐘。清掉時連圖裡的整局記憶一起清（D08 §5、D11 §2、D10 Comments）。
- 已結束的主持，30 分鐘內可以「接著主持」，回到原本的回合與階段，狀態變回進行中（D11 §2）。

### 2.2 權限

- 玩家、店家人員、管理員都能開（D13 §5）。沒登入回 401 `UNAUTHENTICATED`。
- 開了之後，只有開的人與管理員能操作。別人回 403 `PERMISSION_DENIED`（D13 §5）。
- 檢查寫在 `service`，用 `require_role` 與擁有者比對（AGENTS.md §4.5）。

## 3. 流程

### 3.1 節點

沒有新增節點（D23 §6）。API 用 `step`、`turn_number`、`phase_number` 三個欄位表示現在在哪。

| `step` | 中文 | `turn_number` | `phase_number` | 主持人說什麼 | 說完之後 |
|---|---|---|---|---|---|
| `opening` | 開場 | 空 | 空 | 固定台詞：打招呼 | 自動進開局準備 |
| `setup` | 開局準備 | 空 | 空 | 固定台詞：一段話 | 等「下一步」 |
| `night_1` | 夜晚第一步 | 空 | 空 | 固定台詞：口令與倒數 3 秒 | 自動進夜晚第二步 |
| `night_2` | 夜晚第二步 | 空 | 空 | 固定台詞：敲桌子、倒數 10 秒、天亮了 | 自動進第 1 回合階段 1 |
| `turn` | 回合 | 1 起 | 1 | 規則要點：傳金幣、放水晶 | 等「下一步」 |
| `turn` | 回合 | 1 起 | 2 | 規則要點：決定出牌 | 等「下一步」 |
| `turn` | 回合 | 1 起 | 3 | 規則要點：翻牌結算 | 等「下一步」 |
| `ended` | 結束 | 保留結束前的值 | 保留結束前的值 | 固定台詞：結束（三種） | 不動 |

- 開場不唸人數、圓版格數、門檻（D23 §1）。
- 「自動進」的意思：那一段在裝置上**播完**之後，後端自己換到下一個節點（D08 §2）。**「新」** 播完由裝置回報（第 12.3 節的 `playback_done`）。被打斷就不算播完，不會自動往下。
- 主持暫停中，自動進會停住（D11 §3）。

### 3.2 下一步與上一步

「下一步」「上一步」來自按鍵或語音指令，效果相同（D08 §3）。

| 現在 | 下一步 | 上一步 |
|---|---|---|
| 開場 | 開局準備 | 不動 |
| 開局準備 | 夜晚第一步 | **「新」** 開場 |
| 夜晚第一步 | 夜晚第二步 | **「新」** 開局準備 |
| 夜晚第二步 | 第 1 回合階段 1 | **「新」** 夜晚第一步 |
| 第 N 回合階段 1 | 第 N 回合階段 2 | N 大於 1：第 N−1 回合階段 3。**「新」** N 等於 1：夜晚第二步 |
| 第 N 回合階段 2 | 第 N 回合階段 3 | 第 N 回合階段 1 |
| 第 N 回合階段 3 | N 小於圓版格數：第 N+1 回合階段 1。N 等於圓版格數：結束，不分陣營（D23 §5） | 第 N 回合階段 2 |
| 結束 | 不動 | 不動 |

- 換到新節點後，主持人說那個節點的內容（上表「主持人說什麼」）。
- 不動的時候，主持人不出聲。
- 主持暫停中說「下一步」「上一步」或按鍵：照做，暫停解除，被打斷的那一段作廢（D11 §3）。
- 主持人不主動提醒圓版放滿，也不判勝負（D23 §5）。

### 3.3 結束

- 觸發：說「結束了」、說某一方贏了、按「結束主持」、圓版放滿後的「下一步」。
- 語音結束不再確認（D11 §2）。**「新」** 按鍵也不再確認，理由相同：30 分鐘內可以接著主持。
- 結束台詞三種，見第 4.1 節。按鍵與「結束了」用不分陣營的版本。
- 結束後，主持人仍連著，照常回答規則問題。「下一步」「上一步」「暫停」「繼續」不動。

## 4. 主持人說的內容

固定台詞由後端交整句，主持人照唸。規則要點由後端交「要說到哪幾條」，字句由主持人自己組（D23 §3、`GLOSSARY.md`）。測試兩種都只看後端有沒有交出對的內容，不比對主持人說出口的字句（預設 16）。

### 4.1 固定台詞（草稿）

定稿在實作時由立倫試聽（預設 16）。草稿原文在 D23 §4、§8 與 D09 §3，這裡只列代號。

| 代號 | 什麼時候 | 草稿出處 |
|---|---|---|
| `opening` | 開場 | D23 §8 |
| `setup` | 開局準備 | D23 §8 |
| `night_1` | 夜晚第一步，含倒數 3 秒 | D23 §8 |
| `night_2` | 夜晚第二步，含倒數 10 秒與「天亮了」 | D23 §8 |
| `end_white_rose` | 結束，白薔薇贏 | D23 §8 |
| `end_blood_blade` | 結束，血刃贏 | D23 §8 |
| `end_plain` | 結束，沒說哪一方 | D23 §8 |
| `back_to` | 回到第 N 回合的某階段（開場到夜晚時說節點名稱） | D08 §3、D11 §3、D10 §4 |
| `answer_magic_book` | 被問魔法之書 | D23 §4 |
| `answer_winning` | 被問誰贏、幾張了。帶這局的兩個門檻 | D23 §4 |
| `answer_deduction` | 被問誰是血刃、該不該出牌 | D23 §4 |
| `answer_table` | 被問換誰、金幣與水晶在誰手上 | D23 §4 |
| `answer_record` | 要它記戰績或算分 | D23 §4 |
| `answer_not_found` | 規則查不到（第六句） | D13 §4 |
| `wait_lookup` | 查規則前：「我翻一下規則」 | D09 §3 |
| `wait_thinking` | 轉交思考模型前：「讓我來好好的想一想～」 | D09 §3 |
| `wait_longer` | 轉交後第 8 秒 | D09 §3 |
| `not_sure` | 15 秒放棄時補在答案最後 | D09 §4 |

- 結束台詞都不說「辛苦了」（D23 §5）。
- 夜晚的倒數由主持人自己唸出數字，後端不另外計時。
- `answer_*` 六句與 `wait_lookup`、`wait_thinking` 寫在主持人的指令裡，由語音模型自己判斷什麼時候說。其餘由後端在對的時機交給主持人。

### 4.2 規則要點

三個階段各一組，條目在 D23 §3。**第 1 回合交完整版，第 2 回合起交簡短版**。

| 階段 | 完整版 | 簡短版 |
|---|---|---|
| 1 傳金幣、放水晶 | 第 1 到 4 條 | 第 1、3、4 條 |
| 2 決定出牌 | 第 1 到 3 條 | 第 1、2 條 |
| 3 翻牌結算 | 第 1 到 4 條 | 第 1 條，加一句「照翻出來的牌結算」 |

- 用哪一版只看「第幾回合」。上一步、繼續、自動重講都用那個回合該用的版本（D23 §3）。
- 不報第幾回合，不報圓版剩幾格。魔法之書改了流程時，照一般情況說（D23 §3）。
- 來源是 `host` 程式裡的常數，不從規則檢索拿（D13、D21 Comments）。
- **「新」** 交給主持人的格式：一段文字，先寫現在是哪個階段，再寫「請用自己的話說到下面每一條，不要加別的規則」，後面是編號的條目。

### 4.3 主持人的指令

開主持與每次重新連線時，後端把完整指令交給語音模型（D10 §4）。文字由程式組，不叫模型做摘要。指令要包含：

1. 身分：主持人，只說中文（D11 §5）。
2. 固定台詞照唸；規則要點要說到每一條，不加別的規則。
3. 不自己換階段，不自己往下推進流程（D08 §3）。
4. 規則問題一律先呼叫查規則的工具，再回答。例外是語音指令與下面第 6 點的五類（D13 §2）。
5. 查完片段裡沒有答案：說 `answer_not_found`，不猜，不轉交思考模型（D13 §4）。片段裡有相關規則但要推理：轉交思考模型（D09 §2）。
6. 五類問題不查規則，直接說對應的固定回答：魔法之書、問勝負或張數、問推理或打法、問換誰與金幣水晶在誰手上、要它記戰績或算分（D23 §4）。
7. 九項不管的事（D23 §2）：不解釋魔法之書；不判勝負；不讀戰績；不向玩家要陣營、手牌、水晶數字，玩家自己說出來也不重複、不記；不先教整套規則；不計時不催；不點名不追蹤；不主動糾正違規；不給打法建議、不提醒記戰績。
8. 聽到的話不是在問它、也不是語音指令：只呼叫「不回應」工具，不出聲（D11 §4）。
9. 聽到語音指令：呼叫對應的工具，不自己回話。
10. 答完規則問題，補一句 `back_to`，不重講這個階段（D08 §3）。
11. 這局的補充（D13 §3）：白薔薇陣營的門檻、血刃陣營的門檻、圓版格數、「瞞刃就是暗刃」。門檻不主動說，只在 `answer_winning` 與回答勝負規則時說（D23 §4）。
12. 現況：第幾回合、哪個階段、是不是主持暫停中（D10 §4）。

## 5. 語音指令

### 5.1 清單

| 動作 | 說法 | 也接受 |
|---|---|---|
| 暫停 | 「等一下」「暫停」 | |
| 繼續 | 「繼續」 | |
| 下一步 | 「下一步」 | **「新」**「下一部」 |
| 上一步 | 「上一步」 | 「上一部」（D11 Comments 量到的同音字） |
| 結束，不分陣營 | 「結束了」 | |
| 結束，白薔薇贏 | 「白薔薇贏了」 | **「新」**「白薔薇陣營贏了」 |
| 結束，血刃贏 | 「血刃贏了」 | **「新」**「血刃陣營贏了」 |

實作時用真的模型量到別的同音字，再加進「也接受」那一欄。

### 5.2 核對

模型呼叫工具（路 1）與後端看辨識文字（路 2）都要過同一道核對（D11 §2）。

1. 原句有問號（`?`、`？`）：不算。
2. 簡體轉繁體。**「新」** 不新增套件，只用一張小對照表，涵蓋清單上會出現的字。
3. 去掉標點與空白。
4. 開頭有「主持人」就去掉。
5. 剩下的字要**整句等於**清單上的一個說法。

- 核對用的是後端收到的辨識文字，不用模型自己填的字。
- 路 2 也看片段辨識文字（D11 §2）。片段要整句相符才算，所以「等一下再出牌」的片段「等一下」**「新」** 要等 0.3 秒內沒有新的片段才執行。這個數字沒有實測，列進手動檢查。
- 核對沒過：流程不動。路 1 的話，後端告訴模型這不是指令，主持人不出聲（D11 §2）。
- **例外：結束這個動作相信語音模型**（2026-11-22 立倫試聽後決定）。模型呼叫 `end_hosting`，辨識文字不是清單上的說法時：那句話沒有問號、去掉標點後在 8 個字以內，就照樣結束，贏的一方用模型填的 `winner`。
  - 原因：辨識文字幾乎認不出「血刃」。用 5 種台灣口音的合成語音量「血刃贏了」，30 句只有 2 句辨識正確（其他變成「写着名字」「确认延误」等），加同音字補不完；模型自己聽聲音有 21 句呼叫了結束，其中 18 句說是血刃贏。
  - 代價：短句閒聊可能被誤判成結束。結束後 30 分鐘內可以接著主持，回到原本的階段。
  - 辨識文字還沒到、或只有片段時，等完整的辨識文字到了再判斷。其他六個動作不適用這個例外。
- **同一句話只執行一次**。**「新」** 判斷方式：整合層給玩家的每一句話一個編號，辨識文字與工具請求都帶著它；同一個編號的同一個動作，第二次不執行。實作時先確認阿里雲的事件帶不帶得出這個對應；帶不出來就改成「3 秒內同一個動作只執行一次」，並回來更新這一條。
- 按住說話時說語音指令一樣有效，過同一道核對（D11 §1）。

## 6. 主持暫停、繼續與被打斷的那一段

### 6.1 被打斷的那一段

後端記著主持人「正在說、還沒播完」的那一段（D11 §3、D10 §3）。它可能是：

- 一個節點的固定台詞或規則要點。
- 一題規則問題的回答。這時記的是問題與查到的片段（或思考模型的答案），不是主持人說出口的字。

一段在裝置回報播完時清掉。換了節點也清掉。

### 6.2 進入主持暫停

| 原因 | 來源 |
|---|---|
| 說「等一下」「暫停」，或按暫停鍵 | D11 §3 |
| 頁面被切走或鎖屏 | D11 §5 |
| 同一段被閒聊切斷、已自動重講 2 次後又被切斷 | D11 §4 |

- 主持人馬上停，不回話。後端請裝置停播並清空待播內容（第 12.4 節的 `flush`）。
- 暫停中主持人不自己往下走；玩家問規則照常回答，答完還是暫停中（D11 §3）。
- **「新」** 暫停時正在等規則的答案（查規則或思考模型）：答案回來後不唸，記成被打斷的那一段，「繼續」時才說。

### 6.3 繼續

- 觸發：說「繼續」或按鍵。頁面被切走後回來，要先在頁面點一下，那一下就是按「繼續」（D11 §5）。
- 有被打斷的那一段：後端把它重新交給主持人，從頭重講（D11 §3）。不做「從斷掉的那個字接下去」。
- 沒有：主持人只說 `back_to`。
- 不在暫停中說「繼續」：有被打斷的那一段就重講（例如被玩家的問題打斷過），沒有就不動、不出聲。

### 6.4 被打斷之後不自動重講的情況

- 被玩家的規則問題打斷：答完只補 `back_to`。玩家說「繼續」才重講（D11 §3）。
- 按住說話時被按鍵打斷：同上（D11 §3）。

### 6.5 閒聊

- 模型呼叫「不回應」工具，或那句話被判定成不是在跟它說話：後端知道是閒聊（D11 §4）。
- 主持人沒在說話：什麼都不做。
- 主持人那一段因此被切斷：後端自動請主持人重講那一段。同一段最多自動重講 2 次；再被切斷就進入主持暫停（D11 §4）。
- 重講次數在那一段播完或換節點時歸零。

## 8. 查規則與思考模型

### 8.1 主持人的工具

語音模型能呼叫的工具共八個。名稱與參數 **「新」**。

| 工具 | 參數 | 做什麼 | 回給模型 |
|---|---|---|---|
| `lookup_rules` | `question`：玩家的問題 | 查規則原文片段 | 片段清單（頁碼與原文） |
| `ask_thinking_model` | `question` | 後端查片段，再請思考模型回答 | 答案文字 |
| `next_step` | 無 | 語音指令：下一步 | 核對結果 |
| `previous_step` | 無 | 語音指令：上一步 | 核對結果 |
| `pause_hosting` | 無 | 語音指令：暫停 | 核對結果 |
| `resume_hosting` | 無 | 語音指令：繼續 | 核對結果 |
| `end_hosting` | `winner`：`white_rose`、`blood_blade` 或不填 | 語音指令：結束 | 核對結果 |
| `no_reply` | 無 | 這句話不是對主持人說的 | 空的結果，後端不請主持人回答 |

- 五個指令工具的 `winner` 以外都沒有參數：核對用後端自己的辨識文字（第 5.2 節）。`end_hosting` 的 `winner`：辨識文字核對得出來就以辨識文字為準；核對不出來、但符合第 5.2 節的例外時，用模型填的。
- 每個請求跑一次圖（D10 §1）。同一場主持一次只處理一件事，其他的排隊（D10 §6）。

### 8.2 查規則

- `host` 的 `service` 呼叫 `rules_qa` 的新方法（第 13.2 節），拿回最像的 6 段原文片段（D13 §1）。
- 片段原樣交給主持人，魔法之書的也不排除；靠指令回固定台詞（D13 §3）。
- 索引沒建好、找不到這款遊戲、embedding 失敗：一律當成空的結果。主持人照指令說 `answer_not_found`（D13 §4）。後端把原因記進紀錄。
- 整局記憶記下最近 5 題的問題與查到的頁碼（D10 §3）。
- 查的時候，裝置顯示「正在查規則」。

### 8.3 轉交思考模型

- 哪些題轉交由語音模型自己判斷（D09 §2）。一題要轉交時，主持人只說 `wait_thinking`（D09 §3）。
- **「新」** 後端收到 `ask_thinking_model` 後，自己用那個問題再查一次片段，連同問題交給思考模型。這樣主持人不用先呼叫 `lookup_rules`。
- 思考模型走 `integrations/llm`，預設用 `LLM_MODEL`，可用 `HOST_THINKING_MODEL` 換（D09 §2）。
- 計時在圖的外面，屬於轉送那一段（D10 §2）：
  - 從收到工具請求起算。第 8 秒還沒回來：後端請主持人說 `wait_longer`，整段等待只補一次（D09 §3）。
  - 第 15 秒還沒回來，或 `integrations/llm` 回錯誤：放棄。把這次查到的片段交給主持人自己回答，最後補 `not_sure`（D09 §4）。
  - 放棄之後才回來的答案丟掉。
- 等待時裝置同樣顯示「正在查規則」。

### 8.4 等待中玩家又開口

- **「新」** 等待中，玩家又說了一句不是閒聊、也不是語音指令的話：舊題作廢，舊答案晚到也不唸。新的那句由主持人照常處理（新問題就重新查；「算了」就回「好」）（D09 §5）。
- 後端替每一題編號，只把最新那一題的結果交給主持人。
- 作廢的思考模型呼叫不能中途取消，會在背景跑完，答案丟掉（D09 §5）。
- 等待中的閒聊與語音指令不會作廢舊題。

## 10. 連線

### 10.1 保持連線

- 阿里雲 180 秒沒產生回答就斷線（D07）。後端每 150 秒送一則不出聲的系統訊息，帶一句現況（預設 1、D10 §4）。主持人剛說過話就重新算 150 秒。
- 對話歷史設 50 輪（預設 3）。
- 聲音每 20 到 100 毫秒送一小段，單則訊息不能太大（D07）。

### 10.2 後端和阿里雲斷線

- 手機那條連線不斷。後端自己重連，頁面顯示「重新連線中」（預設 2）。
- **「新」** 重試 3 次，間隔 1、2、4 秒。
- 連回來：交完整指令加現況，主持人只說 `back_to`（D10 §4）。主持暫停中連回來就不說。
- 連不回來：送 `HOST_REALTIME_UNAVAILABLE` 再關掉連線（D12 §7）。這場主持照 30 分鐘保留。
- 金鑰錯誤也回 `HOST_REALTIME_UNAVAILABLE`，真正原因只記在後端紀錄（D12 §7）。

### 10.3 後端要主持人開口

固定台詞、規則要點、`wait_longer`、工具結果回來、`back_to`、重講，都是後端主動請主持人開口（預設 5）。

- 等玩家講完、也沒有回答在進行時才送。
- 被拒有兩種：玩家正在說話、另一個回答還在進行（D07）。被拒就重送。
- `wait_longer` 來不及就不補。
- 其他的一直重送，直到送出、換了節點、或進入主持暫停。
- **「新」** 重送的間隔 0.5 秒。

### 10.4 情境

| 編號 | 情境 | 操作 | 預期結果 |
|---|---|---|---|
| K-01 | 主持人 150 秒沒說話 | 假時鐘走 150 秒 | 送出一則系統訊息，內容有第幾回合與階段；沒有請主持人開口 |
| K-02 | 第 100 秒主持人說過話 | 假時鐘再走 100 秒 | 還沒送；到第 250 秒才送 |
| K-03 | 後端和語音模型斷線 | 第 2 次重連成功 | 裝置先收到重新連線中，再收到已連上；交出完整指令加現況 |
| K-04 | 同上 | 3 次都失敗 | 裝置收到 `HOST_REALTIME_UNAVAILABLE`，連線關掉；這場主持還在 |
| K-05 | 後端要交規則要點 | 第一次被拒（玩家正在說話），第二次可以 | 規則要點有送出，只送出一份 |
| K-06 | 後端要交規則要點，一直被拒 | 玩家說「下一步」 | 舊的那份不再重送，改送新階段的 |
| K-07 | 第 8 秒要補 `wait_longer` | 被拒 | 不重送 |
| K-08 | 連線設定 | 檢查交給整合層的設定 | 歷史 50 輪；自動接話時靈敏度 0.5 |

## 11. API：一般請求

路徑照 AGENTS.md §4.3。錯誤格式 `{"error": {"code": ..., "message": ..., "details": {}}}`。

### 11.1 端點

| 方法與路徑 | 用途 | 成功 |
|---|---|---|
| `POST /api/v1/hosting-sessions` | 開一場主持（也是「重新開始」） | 201 |
| `GET /api/v1/hosting-sessions` | 列出自己還保留著的主持（0 或 1 筆），給頁面決定要不要顯示「接著主持」 | 200 |
| `POST /api/v1/hosting-sessions/{id}/connections` | 拿一次性通行碼：接著主持、重整頁面、切換接話方式 | 201 |
| WebSocket `/api/v1/hosting-sessions/{id}/stream?ticket=…` | 聲音與即時訊息，見第 12 節 | — |

- 整組端點 **「新」**。`POST /api/v1/hosting-sessions` 的路徑出自 D12 §5。
- 沒有「結束主持」的一般請求：結束走 WebSocket 的按鍵訊息，因為主持人要唸結束台詞。別人拿不到通行碼，所以結束不了別人的主持。
- 沒有讀取整局記憶或紀錄的端點（D10 §5）。
- 管理員操作別人的主持：用那場主持的 `id` 拿通行碼。`GET` 只列自己的。

### 11.2 `POST /api/v1/hosting-sessions`

請求：

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `player_count` | 整數 | 是 | 5 到 10 |

| `voice` | 字串 | 否 | `male`（預設）或 `female` |

| 欄位 | 說明 |
|---|---|
| `session` | 這場主持，欄位見下表 |
| `connection.ticket` | 一次性通行碼 |
| `connection.expires_at` | 通行碼的期限，60 秒後（D12 §5） |

`session` 的欄位（三個端點都用同一個）：

| 欄位 | 說明 |
|---|---|
| `id` | UUID |
| `status` | `active` 或 `ended` |

### 11.3 `GET /api/v1/hosting-sessions`

回應 200：`{"items": [session], "total": 0 或 1}`。只列自己的、還沒被清掉的。

### 11.4 `POST /api/v1/hosting-sessions/{id}/connections`

請求：`turn_taking_mode`（選填）。有帶而且和現在不同，就是切換接話方式。

回應 201：和 11.2 相同（`session` 加 `connection`）。

- 已結束的主持也可以拿。連上後狀態變回 `active`（D11 §2）。
- 通行碼 60 秒內有效、只能用一次（D12 §5）。

| 沒登入 | 401 | `UNAUTHENTICATED` |

## 12. API：WebSocket

### 12.1 連線

- 裝置把通行碼放在網址上（瀏覽器的 WebSocket 不能自訂標頭，D12 §5）。
- 後端核對通行碼後，才連阿里雲（提早連會開始算 180 秒，D12 §7）。
- 連上後後端先送一則 `state`。
- 同一場主持有第二支裝置連上：先連的那支收到 `HOST_SESSION_TAKEN_OVER`，連線被關掉（D13 §5）。

### 12.2 聲音

| 方向 | 格式 |
|---|---|
| 裝置送 | 二進位訊息，16 kHz、單聲道、16 位元 PCM，每則 20 到 100 毫秒 |
| 後端送 | 二進位訊息，24 kHz、單聲道、16 位元 PCM |

和阿里雲相同，後端不轉檔（D12 §4）。阿里雲的事件不轉給裝置。

### 12.3 裝置送的 JSON 訊息

| `type` | 其他欄位 | 意思 |
|---|---|---|
| `command` | `action`：`next`、`previous`、`pause`、`resume`、`end` | 按鍵。效果和語音指令相同，不用核對 |
| `talk` | `state`：`down`、`up` | 按住說話的按下與放開 |
| `page_hidden` | 無 | 頁面被切走或鎖屏。裝置同時停止收音與播音 |
| `playback_done` | `utterance_id` | 這一段在裝置上播完了 |

- 頁面回來時不送訊息。玩家點「點一下繼續」，裝置送 `command` 的 `resume`。
- 按鍵的結束不帶贏的一方。

### 12.4 後端送的 JSON 訊息

| `type` | 其他欄位 | 意思 |
|---|---|---|
| `state` | `status`、`step`、`turn_number`、`phase_number`、`paused`、`pause_reason`、`looking_up`、`turn_taking_mode`、`voice`、`winner` | 現況。連上時送一次，之後有變就送整份 |
| `utterance` | `utterance_id`、`state`：`start`、`end` | 主持人的一段話開始送、送完。之間的二進位訊息都屬於這一段 |
| `flush` | 無 | 立刻停播並清空待播內容。之後到下一則 `utterance` 的 `start` 之前收到的聲音都丟掉 |
| `connection` | `state`：`reconnecting`、`ready` | 後端和語音模型的連線 |
| `error` | `error`：`code`、`message`、`details` | 錯誤。下表標「關」的，送完就關連線 |

- `pause_reason`：`command`、`page_hidden`、`chatter` 或空。
- `looking_up`：查規則或等思考模型時是真。頁面顯示「正在查規則」。
- 不送主持人或玩家說的文字，不送查到的片段（D10 §5）。

錯誤碼：

| `code` | 什麼時候 | 關 |
|---|---|---|
| `HOST_TICKET_INVALID` | 通行碼不對、過期、用過了 | 關 |
| `HOST_SESSION_NOT_FOUND` | 這場主持不存在或已清掉 | 關 |
| `HOST_SESSION_TAKEN_OVER` | 被別的裝置取代 | 關 |
| `HOST_REALTIME_UNAVAILABLE` | 連不上語音模型，或重連失敗 | 關 |
| `HOST_BAD_MESSAGE` | 裝置送了看不懂的 JSON | 不關，忽略那一則 |

後四個是 **「新」**。`HOST_REALTIME_UNAVAILABLE` 出自 D12 §7。

### 12.5 情境

| 編號 | 情境 | 操作 | 預期結果 |
|---|---|---|---|
| W-01 | 有效的通行碼 | 連線 | 連上；第一則是 `state`；整合層收到開連線的要求 |
| W-02 | 用過的通行碼 | 再連一次 | `HOST_TICKET_INVALID`，關掉 |
| W-03 | 過了 60 秒的通行碼 | 連線 | `HOST_TICKET_INVALID`，關掉 |
| W-04 | 甲那場主持的通行碼 | 連乙那場主持的網址 | `HOST_TICKET_INVALID`，關掉 |
| W-05 | 語音模型連不上 | 連線 | `HOST_REALTIME_UNAVAILABLE`，關掉；這場主持還在 |
| W-06 | 裝置 A 連著 | 裝置 B 用新的通行碼連上 | A 收到 `HOST_SESSION_TAKEN_OVER` 並被關掉；B 正常 |
| W-07 | 連著 | 送聲音 | 整合層收到同樣的資料 |
| W-08 | 連著 | 整合層送出主持人的聲音 | 裝置依序收到 `utterance` 的 `start`、聲音、`end` |
| W-09 | 階段 1 | 送 `command` 的 `next` | 收到新的 `state`，`phase_number` 是 2 |
| W-10 | 連著 | 送 `command`，`action` 是 `jump` | `HOST_BAD_MESSAGE`；連線還在；流程不動 |
| W-11 | 主持人正在說 | 送 `command` 的 `pause` | 收到 `flush`，再收到 `paused` 為真的 `state` |
| W-12 | 連著 | 裝置斷線 | 後端關掉和語音模型的連線；這場主持保留 |
| W-13 | 已結束的主持 | 連上 | `status` 變成 `active`，回合與階段和結束前相同 |

| 介面 | 做什麼 |
|---|---|
| 收音 | 請求麥克風；開始、停止；送出 16 kHz 的 PCM 小段；被拒絕時回報 |
| 播音 | 排進 24 kHz 的 PCM；停播並清空；一段播完時通知；要玩家先點一下才能出聲 |
| 螢幕常亮 | 要求常亮；被系統拒絕時回報 |
| 頁面看不看得見 | 頁面被切走、鎖屏、回來時通知 |

行不通時再回來選 `record` 6.x 或 `flutter_sound`（預設 9）。

### 14.2 `domains/host/data/`

- 三個一般請求的 DTO 與 repository。
- WebSocket 的通道：用 `web_socket_channel`，改成直接宣告（預設 8）。負責二進位與 JSON 訊息的收送。

### 14.3 `domains/host/state/`

一個控制器，參考畫面與正式頁面共用。

狀態：設定值（人數、接話方式、聲線）、有沒有可以接著的主持、連線狀態、`state` 訊息的內容、按住說話鍵是不是按著、提醒（第 14.5 節）。

方法：

| 方法 | 做什麼 |
|---|---|
| 載入 | `GET`，看有沒有可以接著的主持 |
| 開始主持 | 請求麥克風與出聲 → `POST` → 連 WebSocket → 開始收音 → 要求螢幕常亮 |
| 接著主持 | 拿通行碼 → 連 WebSocket |
| 重新開始 | 同「開始主持」 |
| 下一步、上一步、暫停或繼續、結束主持 | 送 `command` |
| 切換接話方式 | 關掉連線 → 帶新的接話方式拿通行碼 → 重連 |
| 按下、放開 | 送 `talk`；按下時本機先停播 |
| 頁面被切走 | 停止收音與播音，送 `page_hidden` |

- 收到 `flush`：停播並清空，丟掉後面屬於舊那一段的聲音。
- 一段播完：送 `playback_done`。
- 測試用 Riverpod 的 override 換成 fake repository 與 fake 通道，放 `frontend/test/support/fakes.dart`（AGENTS.md §7.5）。

## 15. 驗收

### 15.1 兩層

- pytest 與 `flutter test` 用 fake，進 CI，是合併的唯一標準（預設 13）。上面每一張情境表格的每一行都要有對應的測試（AGENTS.md §7.4）。
- 真的模型用手動檢查清單，不進 CI、不擋合併，結果貼進 MR 說明。清單改自原型的 [`auto_checks.py`](prototypes/listen-test/auto_checks.py)。

### 15.2 手動檢查

前置條件：`.env` 有阿里雲與 Azure 的設定；資料庫已建好 `rules_qa` 的白薔薇索引；用手機測要有 HTTPS，由實測的人準備（預設 15）。用筆電開本機網址不需要。

| 要量或要聽的 | 出處 |
|---|---|
| 玩家講完到聽到第一個聲音 | 預設 14 |
| 等待語的第一個聲音、答案的第一個聲音（分開量） | 預設 14 |
| 說「等一下」到聲音停下 | D11 |
| 真人多人桌邊閒聊：亂回應的次數、誤觸發語音指令的次數 | D11 |
| 片段辨識文字等 0.3 秒夠不夠（第 5.2 節） | 這份 |
| 規則題有沒有先查 | D13 |
| 2 題魔法之書，有沒有回固定台詞 | D13 |
| 查原文片段多等多久（含 embedding） | D13 |
| 簡短版規則要點與四句新的固定回答，聽一遍 | D23 |
| 150 秒那則訊息帶現況後，主持人有沒有開口；算不算進 50 輪 | D10、預設 6 |
| 部署後：經後端轉送多一站慢多少；Azure 對長時間連線有沒有閒置逾時 | D12 |

- 門檻用試聽量到的數字當起點。D07 的「桌邊閒聊 6 句都沒回」與 D11 的合成語音速度，都不能當門檻（D11）。
- 語氣不打分數，由立倫定稿固定台詞時試聽（預設 14）。

### 15.3 已知限制

- 只支援中文。
- 每位組員的資料庫要先建好 `rules_qa` 的白薔薇索引，不然問規則一律回 `answer_not_found`。
- 夜晚第二步會提到桌上的備用雙刃牌，但開局準備沒有叫玩家放（D23）。
- 魔法之書改了流程時，主持人說的規則要點會和書上不一致（D23）。
- 規則原文有雜訊與錯字，圖上的字沒有入庫，暫不修正（D16）。
- 後端重啟，所有進行中的主持都會消失；後端只能有一台（D12 §8）。
- 鎖屏後不保證能收音與播音，所以頁面被切走就暫停（D05、D11）。
- 說完「等一下」後，主持人可能還會多說一小段才停，要看片段辨識文字多快到（D11）。
