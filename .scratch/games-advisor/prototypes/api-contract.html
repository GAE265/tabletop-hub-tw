推薦 Agent API 草圖 PROTOTYPE，可丟棄；資料全是假的

這頁要回答：玩家送出一則訊息時，前端送什麼、後端回什麼、出錯時畫面怎麼變？左邊是聊天畫面草圖，右邊是每一步的請求、回應和前端記住的東西。

決定（2026-11-08 和立倫定案）

API 格式

D1路徑 POST /api/v1/advisor/messages，成功回 201。推薦 Agent 只有一個，所以 advisor 用單數；送出一則訊息＝新增一筆訊息（§4.3「不是增刪改查的動作，當成新增子資源」）。後端不存對話，所以沒有 GET。
D2請求只有兩欄：content（去掉前後空白後 1–500 字）、previous_response_id（新對話給 null）。
D3回應四欄：response_id、reply、relaxed_constraint（playtime／age／null，整則訊息一個值，因為同一則的卡片都來自同一次查詢）、recommendations。每張卡片分三塊：game（程式從資料庫填）、reason（LLM 寫）、excerpts（被引用的心得片段）。追問、離題時 recommendations 是空陣列。
D4錯誤碼：
情況狀態碼error.code畫面
欄位錯誤（空白、超過 500 字）422VALIDATION_ERROR（框架預設）前端先擋；萬一發生，同「暫時無法回應」
未登入（只在 JWT 模式）401UNAUTHENTICATED請先登入
對話過期或 id 錯（LLMConversationNotFound）404GAMES_ADVISOR_CONVERSATION_NOT_FOUND清空畫面、顯示「對話已失效」、剛剛那句放回輸入框
Azure 暫時連不上，LLM 或 embedding 都算（LLMUnavailable、EmbeddingError）503GAMES_ADVISOR_UNAVAILABLE剛剛那句從畫面拿掉、放回輸入框，提示再送一次
其他程式錯誤（LLMError 等）500INTERNAL_ERROR（現有）同上
網路斷線、後端沒開—NETWORK_ERROR（前端產生，現有）同上

503 不在 §4.3 的清單裡，要由你向組員提議補進去（AI 不改 AGENTS.md）。

D5固定文字有兩種：模型拒答或內容被過濾、推薦全部被程式丟掉。都回 201，response_id 回請求帶來的舊 id（第一則就回 null），這則訊息不算進對話。

行為

D6不串流，整則一次回來，等待時顯示「正在找桌遊…」。理由：dio 在 Flutter Web 讀不到串流，要另加套件；呼叫工具的那段時間本來就沒有字可以顯示；最終輸出是 JSON；重點是卡片，reply 很短。前端的等待上限要比後端長（後端最多呼叫 LLM 3 次，每次上限 60 秒）。
D7玩家、店家人員、管理員都能用，所以沒有 403；未登入回 401。「沒有權限」的測試案例就是未登入。

畫面（Flutter 參考畫面照這個做）

D8只顯示心得片段原文，不顯示來源（標題、網站名稱、連結）；立倫決定，接受著作權法第 64 條「引用要明示出處」的風險。片段預設摺疊成「心得片段（2）」，點開才看；英文片段旁標「英文」。左邊畫面上方可以切三種顯示方式比較看看。
D9放寬條件顯示成卡片上方一行提示，不是每張卡片各標一次。
D10空畫面放 3 個範例按鈕，點了直接送出（Demo 時少打字）；輸入框下方固定一行「想問規則或玩法？到規則問答」；「開始新對話」不跳確認視窗。

後端（假的）

玩家送出後，畫面停在「載入中」，按「讓後端回應」才會收到回應。

前端記住的東西

黃底＝這一步剛改變的欄位。重新整理頁面就全部清空（後端不存對話，前端也不存進瀏覽器）。

最近一次 API 往返

還沒送出任何訊息。
