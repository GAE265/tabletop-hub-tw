# 心得來源走哪條路

Type: grilling
Status: open
Blocked by: 15
Map: [桌遊推薦 Agent + 桌遊 RAG](../map.md)

## Question

「英文與繁中心得從哪裡取得」的結論是：在預設條款下，沒有任何來源同時允許保存原文、又允許交給 LLM 產生標籤。決定心得要從哪裡來：

- (a) 向 BGG 申請非商業用途的書面同意
- (b) 向繁中部落格作者個別取得同意，例如方格子的作者
- (c) PTT BoardGame 板屬於灰色地帶，組內同意後當次要來源
- (d) 由組員或合作店家人員自己寫心得
- (e) 不用心得，標籤改從其他資料產生，例如資料來源的類別與機制、人工標註
- 或以上幾種組合

一併決定：

1. 需求 2「收集心得、自動產生標籤」要不要調整，調整後怎麼跟組員說明。
2. 誰負責實際收集。AI 助理不代抓擋了 AI 代理的網站。
3. 要不要保存原文；不保存時，只保存哪些衍生資料，例如標籤與來源網址。

## Comments

- 2026-11-06：「核對 BGG 使用條款原文」已結案。BGG 現行條款允許把內容交給 LLM 做摘要等一般用途，所以選項 (a) 不必為了 AI 用途另外申請書面同意，只要註冊 XML API application 取得 token。BGG 評分留言是否能保存原文，仍待確認。
- 2026-11-06：PTT 的篇數統計因取得方式不符合 robots.txt 已刪除。若要把 PTT 列入考慮，討論前請組員用瀏覽器手動查幾款遊戲的 `[心得]` 文數量。
- 2026-11-07：立倫表示 BGG 的規定不在他的處理範圍，以完成負責的功能模組為優先。BGG 評分留言能不能保存原文不會再另外核對，這張直接依現有資訊決定。
- 2026-11-07（來自「[條件與偏好怎麼比對桌遊](10-matching-strategy.md)」）：embedding 用在兩處，都需要心得：心得摘要（排序）與心得片段（推薦理由的出處）。選項 (e)「不用心得」會讓兩種向量都沒有資料。心得片段要把文字存進資料庫（資料庫不是 repo，原文仍不進 repo）。
