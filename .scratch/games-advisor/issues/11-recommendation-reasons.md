# 推薦理由要寫什麼、要不要附出處

Type: grilling
Status: open
Blocked by: 09, 10
Map: [桌遊推薦 Agent + 桌遊 RAG](../map.md)

## Question

1. 每款推薦的理由要包含什麼：符合哪些條件、命中哪些偏好與標籤。
2. 要不要附心得出處（連結或摘錄）；若要附，使用條款允許顯示到什麼程度。
3. 理由由 LLM 產生還是用模板組合；怎麼避免 LLM 寫出資料裡沒有的特性。

## Comments

- 2026-11-07（來自「[Agent 怎麼追問、什麼時候推薦](07-conversation-flow.md)」）：只能推薦工具回傳的桌遊；推薦結果用什麼格式交給程式檢查，在這張或「API 契約與 prototype 頁面」決定。條件被放寬時（時長或年齡），回覆要明說哪一項沒有符合。BGG 的英文類別與機制名稱，回覆時翻成中文；回覆一律用繁中。
- 2026-11-07（來自「[標籤詞彙表怎麼定](08-tag-vocabulary.md)」）：每個標籤有繁中名稱和一句繁中定義，可以直接用在理由裡；每款的每個標籤有 0–1 的信心分數，理由要不要提到在這張決定。
- 2026-11-07（來自「[條件與偏好怎麼比對桌遊](10-matching-strategy.md)」）：「查桌遊」工具回傳前 3 款，每款附上命中的偏好（標籤、類別、機制、難度）、命中的負面偏好，以及最相近的 2 段心得片段（每段帶片段 ID）。立倫決定理由要用心得片段當出處；service 會檢查 LLM 引用的片段 ID 都在回傳範圍內。這張要決定：理由怎麼引用片段、出處顯示到什麼程度（摘錄、連結）、推薦結果交給程式檢查的格式。
