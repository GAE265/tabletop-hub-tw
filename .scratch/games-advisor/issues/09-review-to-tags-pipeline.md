# 心得怎麼變成標籤

Type: grilling
Status: open
Blocked by: 03, 08, 16
Map: [桌遊推薦 Agent + 桌遊 RAG](../map.md)

## Question

決定離線批次管線：

1. 步驟：收集心得、清理、分析、彙整成每款桌遊的標籤。每一步的輸入與輸出是什麼。
2. 心得原文存不存、存在哪裡（不得進 repo）；要保留哪些追溯資訊，例如來源網址、語言、日期。
3. 一款桌遊的心得很多時怎麼處理，例如抽樣或逐段彙整。
4. 批次指令放在 `backend/` 的哪裡、怎麼執行、失敗後能不能從中斷處繼續。
5. 怎麼檢查產生的標籤合不合理。

## Comments

- 2026-11-07 立倫：標籤是用語意分析讀心得後得到的結果，準確度可能需要人工驗證。決定管線時要包含人工驗證的步驟。
- 2026-11-07（來自「[標籤詞彙表怎麼定](08-tag-vocabulary.md)」）：詞彙表先從心得歸納再固定：LLM 自由擷取候選詞 → 合併同義詞 → 立倫審核（最多約 30 個）→ LLM 照詞彙表上標籤（enum）。每個標籤有英文代碼、繁中名稱、一句繁中定義；有 4 類內容不能變成標籤（見該 ticket）。這張要決定：歸納與審核的步驟、信心分數（0–1，由 LLM 給）的給分標準、逐則心得還是整款桌遊給分、人工驗證刪除標籤的流程（只能刪，不能新增或改分數）、詞彙表定案後存在哪裡。
- 2026-11-07（來自「[條件與偏好怎麼比對桌遊](10-matching-strategy.md)」）：管線除了標籤，還要產出兩種 embedding 的資料：(1) 每款桌遊一段繁中心得摘要（描述玩起來的感受）與摘要向量，寫進桌遊資料表新增的兩個欄位；(2) 從心得切出心得片段，每段轉成向量，存進新的心得片段資料表（`game_id`、片段文字、片段向量）。這張要決定摘要的長度與產生方式、片段怎麼切、片段存原文還是翻譯，以及片段資料表的其他欄位。信心分數門檻暫定 0.5（低於門檻當作沒有這個標籤），定好給分標準後回頭確認。
