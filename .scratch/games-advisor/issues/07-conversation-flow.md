# Agent 怎麼追問、什麼時候推薦

Type: grilling
Status: resolved
Blocked by: 06
Map: [桌遊推薦 Agent + 桌遊 RAG](../map.md)

## Question

決定對話流程：

1. Agent 要釐清哪些條件與偏好；哪些條件是必要的，缺少時一定要追問。
2. 玩家的話怎麼歸類成條件或偏好，例如「最好 90 分鐘內」、「不要太燒腦」。
3. 什麼時候停止追問、開始推薦；最多追問幾輪。
4. 推薦後玩家可以怎麼調整，例如「換一款不要運氣成分的」。
5. 一次推薦幾款；找不到符合條件的桌遊時怎麼回覆。
6. 回覆語言：只用繁中，還是跟著玩家的語言。

## Answer

2026-11-07 與立倫 grilling 定案（4 輪）。

**流程由 LLM 決定，程式只守護欄**

推薦 Agent 依一份對話規則（每輪重送的 `instructions`），自己判斷繼續追問還是推薦。資料夠了，就呼叫「查桌遊」工具（function calling）。

- 條件與偏好每次都完整放在工具參數裡，後端不另外保存狀態，配合「[對話狀態存在哪裡](05-conversation-state.md)」的決定。「[RAG 教材有哪些可以重用](01-rag-materials-reuse.md)」提到的「每輪擷取變動欄位、由程式合併」不採用。
- 沒有採用的方案：每輪由 LLM 做結構化擷取，再由 service 照規則判斷追問或推薦。這個方案比較容易用 pytest 驗證，但立倫選擇讓 Agent 依對話規則判斷。理由與後果寫成 [ADR 0002](../../../docs/adr/0002-games-advisor-llm-driven-conversation-flow.md)（proposed），等組員決定。

三道程式護欄：

1. **工具參數的人數必填**；時長、年齡、偏好、排除清單可以不填。service 收到不合理的人數（例如 0 或 50）時，把錯誤回給 LLM，讓它向玩家確認。
2. **只推薦工具回傳的桌遊**，不能推薦沒收錄的遊戲。推薦結果用什麼格式交給程式檢查，由「推薦理由要寫什麼」與「API 契約與 prototype 頁面」決定。
3. **玩家每送一則訊息，最多呼叫 2 次工具。**

驗證分工：

- pytest 驗：工具的篩選、人數必填、呼叫次數上限。
- 情境題組驗：該追問時有沒有追問、放寬順序、離題處理，由「怎麼驗收推薦結果」用真的模型檢查。

**1. 條件與偏好**

- **依欄位歸類，不看語氣。** 提到人數、時長、年齡，一律是條件，例如「最好 90 分鐘內」就是時長 ≤ 90 的條件。其他特性一律是偏好，例如「不要太燒腦」對應難度。
- **只有人數是必要條件。** 沒提時長、年齡就不篩，也不另外追問。
- **負面偏好只排後面，不排除。** 例如「不要運氣成分」，有擲骰的卡坦島只會排後面。扣分多重由「條件與偏好怎麼比對桌遊」決定。

**2. 追問規則**（寫進對話規則）

1. 玩家只講人數、沒提偏好時，追問一次偏好，給 2–3 個選項，例如「輕鬆聊天、動腦策略、大家合作」。玩家回「都可以」就直接推薦。
2. 要追問時，缺的項目一次問完。
3. 最多追問 2 輪，之後只要有人數就推薦。人數例外：沒有人數就繼續追問，而且只問人數。

**3. 推薦**

- 一則訊息最多推薦 3 款，符合的不到 3 款就照實際數量。工具回傳幾款、怎麼排序，由「條件與偏好怎麼比對桌遊」決定。
- 回覆一律用繁中（台灣用語）。玩家用英文也聽得懂，但用繁中回答；BGG 的英文類別與機制名稱，回覆時翻成中文。

**4. 找不到符合條件的桌遊**

- 由 LLM 放寬一項條件，重新呼叫工具，並在回覆中明說放寬了哪一項，例如「沒有 15 分鐘內能玩完的，以下是時長稍長的」。
- 先放寬時長，再放寬年齡，最多只放寬一項。第 1 次查詢 0 款、第 2 次放寬後再查，剛好用完 2 次的呼叫額度；如果還是 0 款，就告訴玩家沒有符合的桌遊，問要怎麼調整。
- **人數不放寬。** 只有人數造成查無結果時（例如 12 人），回覆沒有支援這個人數的桌遊，建議分桌，並問每桌幾個人。
- `GLOSSARY.md` 的「條件」已改寫，把這個例外寫進定義。

**5. 推薦後調整**

1. 玩家加了偏好（例如「換一款不要運氣成分的」）：LLM 加上新的偏好重新查詢，並把這段對話已經推薦過的桌遊放進排除清單。
2. 玩家改了條件（例如「其實有 5 個人」）：用新條件重新查詢。
3. 全部排除後沒有符合的桌遊時，照第 4 點處理。

**6. 離題**（原本列在 map 的「Not yet specified」，併進這張）

1. 問已推薦桌遊的基本資料（例如「卡坦島要玩多久？」）：用對話中工具回傳的資料回答，資料裡沒有的就說不知道。
2. 問規則或玩法：不解釋，請玩家改用規則問答功能（`rules_qa`）。
3. 和桌遊推薦無關的話題：簡短拒絕，把話題帶回推薦。

**術語**：`GLOSSARY.md` 提案區改寫「條件」，新增「推薦 Agent」、「推薦」、「追問」。
