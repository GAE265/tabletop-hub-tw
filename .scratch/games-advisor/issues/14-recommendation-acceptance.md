# 怎麼驗收推薦結果

Type: grilling
Status: open
Blocked by: 07, 10
Map: [桌遊推薦 Agent + 桌遊 RAG](../map.md)

## Question

1. 自動化測試（pytest 加 `FakeLLMProvider`）要驗什麼：條件篩選、追問流程、錯誤處理。
2. 推薦品質用什麼方式評估：自訂的玩家情境題組、「符合全部條件」與「符合部分條件」分開計分、人工檢查。
3. 題組要幾題、放在哪裡（不得含心得原文）。

## Comments

- 2026-11-07（來自「[對話狀態存在哪裡](05-conversation-state.md)」）：後端不存對話，不能從資料庫拿真實對話重跑；真實對話只能在 30 天內用 Azure 的 response id 讀回。
- 2026-11-07（來自「[Agent 怎麼追問、什麼時候推薦](07-conversation-flow.md)」）：pytest 驗工具篩選、人數必填、每則訊息最多呼叫 2 次工具。以下行為由 LLM 判斷，要放進情境題組用真的模型檢查：沒有人數時只問人數；沒提偏好時追問一次並給選項；最多追問 2 輪；查無結果先放寬時長、再放寬年齡，最多一項，且回覆要說出來；人數不放寬並建議分桌；推薦後調整時不再出現推薦過的桌遊；離題的三種處理；一律用繁中回覆。情境題組要怎麼放進 AGENTS.md §7「測試是唯一標準」，見 ADR 0002。
- 2026-11-07（來自「[條件與偏好怎麼比對桌遊](10-matching-strategy.md)」）：pytest（假的 repository、fake embedding）驗：條件篩選、人數 1–30、負面偏好排後面、RRF 合併、沒有偏好時依難度再依名稱、回傳最多 3 款、片段 ID 檢查。情境題組用真的模型檢查：詞彙表對不到的偏好（例如「適合約會」）有沒有影響排序、繁中 `preference_text` 找英文心得片段的效果。
