# 標籤詞彙表怎麼定

Type: grilling
Status: resolved
Blocked by: 01, 03
Map: [桌遊推薦 Agent + 桌遊 RAG](../map.md)

## Question

1. 標籤用固定的詞彙表，還是讓 LLM 自由產生。若用固定詞彙表，從哪裡來（BGG 類別與機制、自訂、兩者混合），大約幾個。
2. 英文與繁中心得怎麼對應到同一個標籤，例如每個標籤都有中英兩種名稱。
3. 一款桌遊的標籤要不要有強度或信心分數。
4. 標籤要不要分組，例如主題、機制、氛圍、適合對象。

## Answer

2026-11-07 與立倫 grilling 定案（4 輪）。

**1. 詞彙表先從心得歸納，再固定**

1. LLM 從心得自由擷取候選詞。
2. 合併同義詞。
3. 立倫審核，定成標籤詞彙表，最多約 30 個。
4. LLM 照詞彙表替每款桌遊上標籤，只能選詞彙表裡的代碼（strict schema 的 enum）。

- 詞彙表要等心得收集完才產生得出來，實際步驟由「[心得怎麼變成標籤](09-review-to-tags-pipeline.md)」決定。
- 沒有採用的方案：
  - AI 助理自訂固定詞彙表：立倫要詞彙來自心得。
  - 完全自由、不合併同義詞：「好笑」和「funny」對不起來，工具參數也不能用 enum。
  - 每款桌遊各自合併：不同桌遊之間對不起來，例如「勾心鬥角」和「互相猜忌」。

**2. 每個標籤的內容**

| 欄位 | 例子 |
|---|---|
| 英文代碼 | `laughter` |
| 繁中名稱 | 歡樂爆笑 |
| 繁中定義（一句） | 玩的過程常有大笑、吵鬧的場面 |

- 中英心得對到同一個標籤：LLM 讀定義後選代碼，英文心得的 "hilarious" 和繁中心得的「笑到不行」都對到 `laughter`。
- 不存英文名稱，因為回覆一律用繁中。
- 不分組：比對和顯示都用不到組別，之後需要再加欄位。

**3. 什麼能變成標籤**

- 只描述玩起來的感受，例如氣氛、互動方式、運氣影響、適合的場合、美術與配件。
- 不能變成標籤的 4 類：
  1. 整體好壞的評價：好玩、無聊、推薦。
  2. 和條件重複：很快玩完（時長）、適合小孩（年齡）、4 人最好玩（最佳人數，已決定不處理）。
  3. 和 BGG 類別、機制、難度重複：合作（`Cooperative Game`）、陣營對抗（`Team-Based Game`）、容易上手（難度）。
  4. 價格、版本、翻譯品質、購買管道。
- 每個面向只保留一個方向，例如只設「運氣影響大」，不設「運氣影響小」。
- 一款桌遊沒有某個標籤，只代表心得沒有明顯提到，不代表相反。玩家說「不要靠運氣的」，就把「運氣影響大」當負面偏好。

**4. 信心分數**

- 每款桌遊的每個標籤各有一個 0–1 的信心分數，由 LLM 依心得給。LLM 只輸出它判斷這款桌遊有的標籤。
- 分數在批次時產生並存下來，推薦時只讀存好的值。
- 名稱用「信心分數（confidence）」，不用 `weight`，避免和難度撞名。
- 沒有採用的方案：程式計算提及比例（例如 40 則心得有 18 則提到就是 0.45）。這個方案可以重現、可以寫測試，但立倫選擇由 LLM 給分。

**5. 人工驗證**

- 只能刪除標籤，不能新增，也不能改信心分數。
- 標籤明顯缺漏時，代表心得不夠，要補心得重跑，不手動補標籤。

**術語**：`GLOSSARY.md` 改寫「標籤」（例子換成「歡樂爆笑」、「運氣影響大」，並說明沒有標籤不代表相反），新增「標籤詞彙表」、「信心分數」。

  - LLM 逐則心得給分，還是一次讀完整款桌遊的心得再給分。
