# home-page Specification

## Purpose

首頁（`/`）：Demo 給評審看，所有角色同一個畫面，把人最快送到下一步（找遊戲、揪團、訂位、學規則），並列出目前使用者接下來的行程。

## Requirements

### Requirement: 首頁內容與入口
路由 `/` SHALL 顯示首頁，所有角色（player、shop_staff、admin）看到相同的內容：品牌名「遊任有娛」、登入按鈕、主標「今天想怎麼玩？」、副標「找遊戲、揪人、訂位、學規則，一個地方搞定。」、四張入口卡片與「接下來的行程」。入口卡片 MUST 依序為：

| 標題 | 說明文字 | 導向 |
|---|---|---|
| 今天玩什麼？ | 跟助理聊聊，幫你挑遊戲 | `/games-advisor` |
| 找人一起玩 | 開團或加入，額滿可候補 | `/groups` |
| 訂個位子 | 挑桌遊店，直接選座位 | `/booking` |
| 這遊戲怎麼玩 | 看教學、隨時問規則 | `/rules` |

首頁 MUST NOT 顯示戰績與天梯、健康狀態。

#### Scenario: 開啟首頁
- **WHEN** 使用者前往 `/`
- **THEN** 顯示品牌名、登入按鈕、主標、副標、四張入口卡片（標題與說明文字如上表）與「接下來的行程」

#### Scenario: 所有角色同一個畫面
- **WHEN** 分別以 player、shop_staff、admin 開啟首頁
- **THEN** 品牌、主標、四張入口卡片與「接下來的行程」標題都相同

#### Scenario: 點入口卡片
- **WHEN** 使用者點「今天玩什麼？」「找人一起玩」「訂個位子」「這遊戲怎麼玩」
- **THEN** 分別前往 `/games-advisor`、`/groups`、`/booking`、`/rules`

#### Scenario: 登入按鈕尚未開放
- **WHEN** 使用者點登入按鈕
- **THEN** 顯示「登入功能即將推出」提示，停留在首頁

#### Scenario: 手機排列
- **WHEN** 畫面寬度為手機（< 600）
- **THEN** 入口卡片排成兩欄兩列

#### Scenario: 桌機排列
- **WHEN** 畫面寬度為桌機（≥ 1024）
- **THEN** 四張入口卡片排在同一列

#### Scenario: 健康檢查頁移到 /health
- **WHEN** 開發者前往 `/health`
- **THEN** 顯示原本的健康檢查頁；首頁與導覽列都沒有它的入口

### Requirement: 接下來的行程
首頁 SHALL 列出目前使用者即將到來的訂位與揪團，依開始時間由近到遠排序，最多 5 筆：

- 訂位：狀態為已確認（`confirmed`），且開始時間在現在之後。
- 揪團：目前使用者是成員或候補（`my_status` 為 `member` 或 `waitlisted`），且開始時間在現在之後；已取消的揪團不列出。

每一列 SHALL 顯示日期（台灣時間的月、日）與：

- 訂位：「訂位・<開始時間>・<人數> 人」、店家名稱與桌號、狀態「已確認」；點選前往 `/booking/mine`。
- 揪團：「揪團・<揪團名稱>」、「已報名 <成員數> / <預計人數> 人」、狀態（我是候補時顯示「候補中」，否則有名額顯示「招募中」、額滿顯示「已額滿」）；點選前往 `/groups`。

這一區的載入中、沒有資料、錯誤 MUST 只影響這一區，入口卡片照常顯示與可點。

#### Scenario: 有訂位也有揪團
- **WHEN** 使用者有一筆 11/21 19:00 的已確認訂位，並已報名一個 11/22 的揪團
- **THEN** 依序顯示訂位一列、揪團一列，內容如上述格式

#### Scenario: 只列即將到來的
- **WHEN** 使用者有已取消的訂位、已完成的訂位、開始時間已過的訂位與揪團
- **THEN** 這些都不列出

#### Scenario: 候補中的揪團
- **WHEN** 使用者在某個揪團是候補
- **THEN** 這一列的狀態顯示「候補中」

#### Scenario: 額滿的揪團
- **WHEN** 使用者是成員，且揪團剩餘名額為 0
- **THEN** 這一列的狀態顯示「已額滿」

#### Scenario: 超過 5 筆
- **WHEN** 即將到來的訂位與揪團合計 7 筆
- **THEN** 只顯示時間最近的 5 筆

#### Scenario: 點行程
- **WHEN** 使用者點訂位列或揪團列
- **THEN** 分別前往 `/booking/mine` 或 `/groups`

#### Scenario: 載入中
- **WHEN** 行程資料尚在載入
- **THEN** 行程區顯示載入指示，入口卡片照常顯示

#### Scenario: 沒有行程
- **WHEN** 沒有任何即將到來的訂位與揪團
- **THEN** 行程區顯示空狀態文字，以及「找人一起玩」與「訂個位子」兩個按鈕，分別前往 `/groups` 與 `/booking`

#### Scenario: 載入失敗
- **WHEN** 訂位或揪團的 API 失敗（例如後端無法連線）
- **THEN** 行程區顯示錯誤訊息與「重試」；按「重試」重新載入，成功後顯示行程；入口卡片照常可點

#### Scenario: 店家人員沒有「我的訂位」
- **WHEN** 以 shop_staff 開啟首頁（`GET /api/v1/bookings` 對店家人員回 403）
- **THEN** 不視為錯誤，行程區只列出揪團（沒有揪團時顯示空狀態）

#### Scenario: 切換身分
- **WHEN** 開發者用身分切換器換成另一個帳號
- **THEN** 行程區重新載入，顯示新身分的行程
