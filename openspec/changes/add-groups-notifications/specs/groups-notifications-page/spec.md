# Spec Delta

## Purpose

揪團通知的前端：導覽列的通知鈴鐺與未讀數、通知列表頁、揪團詳細頁的「確定成團」與「已成團」標示。

## ADDED Requirements

### Requirement: 通知鈴鐺
導覽列 SHALL 顯示通知鈴鐺：手機在畫面頂部的一條窄列，平板與桌機在頂部導覽列。有未讀時，鈴鐺上顯示未讀數，超過 99 顯示「99+」；沒有未讀時不顯示數字。進入應用時查詢一次，之後每 60 秒重新查詢。查詢失敗時鈴鐺照常顯示，不顯示數字，也不跳錯誤。點鈴鐺前往 `/groups/notifications`。

#### Scenario: 有未讀
- **WHEN** `unread_count=3`
- **THEN** 鈴鐺顯示「3」

#### Scenario: 超過 99
- **WHEN** `unread_count=120`
- **THEN** 鈴鐺顯示「99+」

#### Scenario: 沒有未讀
- **WHEN** `unread_count=0`
- **THEN** 鈴鐺不顯示數字

#### Scenario: 查詢失敗
- **WHEN** 通知 API 回錯誤
- **THEN** 鈴鐺照常顯示、沒有數字，畫面不跳錯誤

#### Scenario: 定時更新
- **WHEN** 過了 60 秒，後端的未讀數從 1 變成 2
- **THEN** 鈴鐺改成顯示「2」

#### Scenario: 點鈴鐺
- **WHEN** 點鈴鐺
- **THEN** 前往通知列表頁

### Requirement: 通知列表頁
`/groups/notifications` SHALL 依新到舊列出自己的通知。每則顯示：
- 一句說明：
  - 成團：`「揪團名稱」已成團`
  - 解散：`「揪團名稱」已取消`
  - 候補正取：`你已從候補遞補為「揪團名稱」的成員`
- 揪團開始時間（台灣時間）與通知時間。

未讀的通知 MUST 與已讀的看得出差別。點一則通知時，未讀的先標成已讀並更新鈴鐺的未讀數，然後前往該揪團的詳細頁；標成已讀失敗時仍然前往詳細頁。還有下一頁時，捲到底自動載入下一頁。

#### Scenario: 三種通知的文字
- **WHEN** 有成團、解散、候補正取各一則
- **THEN** 依新到舊顯示三句對應的說明與時間

#### Scenario: 點未讀的通知
- **WHEN** 點一則未讀通知
- **THEN** 送出 `PATCH {"read": true}`，那一則變成已讀，鈴鐺少 1，並前往該揪團詳細頁

#### Scenario: 點已讀的通知
- **WHEN** 點一則已讀通知
- **THEN** 不送 `PATCH`，直接前往該揪團詳細頁

#### Scenario: 標成已讀失敗
- **WHEN** `PATCH` 回錯誤
- **THEN** 仍然前往詳細頁，那一則維持未讀

#### Scenario: 載入中
- **WHEN** 列表還在載入
- **THEN** 顯示載入中

#### Scenario: 沒有通知
- **WHEN** 列表為空
- **THEN** 顯示「目前沒有通知」

#### Scenario: 載入失敗
- **WHEN** 列表 API 回錯誤
- **THEN** 顯示中文錯誤訊息（不含錯誤代碼）與「重試」，按重試重新查詢

#### Scenario: 下一頁
- **WHEN** `total` 大於已載入的筆數，且捲到底
- **THEN** 載入下一頁並接在後面

### Requirement: 確定成團按鈕
揪團詳細頁 SHALL 在使用者是開團主、揪團開放中、還沒成團時，顯示「確定成團」（和既有的「取消揪團」一樣只依開團主判斷；後端仍允許 admin）。按下後跳出確認對話框，說明會通知所有成員。確認後送出 `PATCH {"confirmed": true}`，成功後重新載入詳細資料，按鈕變成停用的「已成團」。失敗時顯示中文錯誤訊息，按鈕保留。

已成團且開放中時，所有人（開團主、成員、候補、其他玩家）的按鈕列都有一顆停用、按不下去的「已成團」；開團主的「確定成團」由它取代。

#### Scenario: 開團主看到按鈕
- **WHEN** 開團主打開自己開放中、還沒成團的揪團
- **THEN** 看到「確定成團」

#### Scenario: 其他人看不到
- **WHEN** 成員、候補或其他玩家打開揪團
- **THEN** 沒有「確定成團」

#### Scenario: 已成團
- **WHEN** 開團主打開已成團的揪團
- **THEN** 沒有「確定成團」，原位置是停用的「已成團」

#### Scenario: 其他人看到已成團
- **WHEN** 成員、候補或其他玩家打開已成團的揪團
- **THEN** 按鈕列有停用的「已成團」

#### Scenario: 已取消、已結束
- **WHEN** 開團主打開已取消或已結束的揪團
- **THEN** 沒有「確定成團」，也沒有「已成團」

#### Scenario: 確定成團
- **WHEN** 開團主按「確定成團」並在對話框按確定
- **THEN** 送出 `{"confirmed": true}`，之後「確定成團」變成停用的「已成團」

#### Scenario: 對話框按取消
- **WHEN** 在對話框按取消
- **THEN** 不送出任何請求

#### Scenario: 確定成團失敗
- **WHEN** API 回 409
- **THEN** 顯示中文錯誤訊息，按鈕保留

### Requirement: 已成團標示
`confirmed_at` 不為空且揪團開放中時，月曆列表的揪團卡片 SHALL 顯示「已成團」標籤（詳細頁由停用的「已成團」按鈕表示，資訊卡不重複顯示）。已取消或已結束時，顯示原本的狀態，不顯示「已成團」。

#### Scenario: 卡片顯示已成團
- **WHEN** 月曆當天列表有一個已成團、一個未成團的揪團
- **THEN** 只有前者的卡片顯示「已成團」

#### Scenario: 成團後取消
- **WHEN** 已成團的揪團被取消
- **THEN** 顯示「已取消」，不顯示「已成團」

### Requirement: 揪團詳細頁的網址
`/groups/<揪團 id>` SHALL 直接顯示該揪團的詳細頁（和從月曆點進去的是同一個頁面），導覽列選取「揪團」。`/groups/notifications` 仍是通知列表頁，不被當成揪團 id。

#### Scenario: 開啟揪團網址
- **WHEN** 前往 `/groups/g-1`
- **THEN** 顯示揪團 g-1 的詳細頁

#### Scenario: 通知列表的網址
- **WHEN** 前往 `/groups/notifications`
- **THEN** 顯示通知列表頁，不是揪團詳細頁
